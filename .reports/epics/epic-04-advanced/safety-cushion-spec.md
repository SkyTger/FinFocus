# Epic-04: Финансовая подушка безопасности (Safety Cushion)

**Статус:** Plan Mode  
**Дата начала:** 2026-01-26  
**Целевой срок:** TBD (после планирования батча)  

---

## Обзор

Финансовая подушка безопасности — это концепция, которая помогает пользователю определить и отслеживать **минимально допустимый остаток денег** для безопасности, а также накопить **целевую сумму резерва** на случай экстренных ситуаций. Подушка работает в двух слоях: как **цель для накопления** и как **пороговая линия в кассовом календаре**, помогая пользователю избежать финансовых рисков.

---

## Scope

### Must Have (MVP)
- Карточка настройки подушки: задание цели, порога (минимального остатка), опциональные сценарии.
- Система расчёта рекомендуемой цели по сценариям (два режима: "Сумма всех сценариев" или "По самому дорогому").
- Визуализация порога в кассовом календаре: подсветка дней ниже порога, маркер первого дня пересечения.
- KPI в шапке календаря: информация о недостатке до порога на конец месяца.
- Дефицит в ячейках дней: округлённое значение "−X тыс. ₽" для дней ниже порога.

### Should Have
- Сценарии как кастомные ярлыки причин использования подушки (медицина, авто, потеря дохода и т.п.).
- Быстрый старт: шаблоны сценариев для быстрого выбора.

### Could Have
- Аналитика использования подушки: сколько раз и на что была потрачена.
- Mobile компактный режим: переключатель "Показать дефицит" для сокращения визуальной нагрузки на сетке.

### Won't Have
- Отдельный счёт/кошелёк для подушки (подушка — концепт, не отдельная сущность в БД).
- Автоматическое блокирование операций при падении ниже порога.
- AI/умные рекомендации размера подушки.

## Структура данных

### User.safety_cushion_goal
```
- goal: Decimal (целевая сумма подушки)
- threshold: Decimal (минимальный остаток; по умолчанию = goal * 0.30)
- scenarios: List[SafetyCushionScenario] (опционально)
```

### SafetyCushionScenario
```
- id: str
- name: str (название сценария: "Медицина", "Авто", "Потеря дохода" и т.п.)
- min_amount: Decimal (нижняя граница)
- max_amount: Decimal (верхняя граница)
- user_id: FK
```

### UI-Контекст (dcc.Store)
- `safety-cushion-mode`: режим расчёта ("sum" / "max_scenario")
- `safety-cushion-recommended`: рекомендованная цель (результат расчёта)

## UX: Карточка подушки

### Макет (примерный)

```
┌─────────────────────────────────┐
│  Финансовая подушка             │
├─────────────────────────────────┤
│                                 │
│  Цель подушки                   │
│  [______ 150 000 ₽____]         │
│                                 │
│  Минимальный остаток            │
│  [______ 45 000 ₽___]           │  (по умолчанию 30% от цели)
│  (редактируется отдельно)       │
│                                 │
│  [━━━━━━━━━━════════] 70%      │  (прогресс-бар)
│   ↑ маркер порога (30%)         │
│                                 │
│  ⌄ Рассчитать по сценариям     │
│  ┌──────────────────────────┐   │
│  │ Сценарий 1               │   │
│  │ Медицина: 10k - 50k      │   │
│  │                          │   │
│  │ Сценарий 2               │   │
│  │ Авто: 15k - 80k          │   │
│  │                          │   │
│  │ + Добавить сценарий      │   │
│  │                          │   │
│  │ Режим расчёта:           │   │
│  │ ( ) Сумма сценариев      │   │
│  │ (●) По самому дорогому   │   │
│  │                          │   │
│  │ Рекомендованная цель:    │   │
│  │ 80 000 ₽                 │   │
│  │ [Применить рекомендацию] │   │
│  └──────────────────────────┘   │
│                                 │
└─────────────────────────────────┘
```

### Поведение

1. **Цель подушки (input)**
   - Обязательное поле, можно задать любое число ≥ 0.
   - При изменении: если пользователь не редактировал порог вручную, пересчитать порог на 30% от новой цели.

2. **Минимальный остаток (input)**
   - По умолчанию = 30% цели.
   - Как только пользователь вводит вручную — запомнить этот выбор и не переписывать автоматически.
   - Можно задать любое число (в том числе 0).

3. **Прогресс-бар**
   - Заливка: 0 → цель (зелёная/нейтральная).
   - Маркер (вертикальная полоска): на 30% (или на месте пользовательского порога).
   - Label: "X% накоплено" (если текущая цель известна из другого источника) или просто "0 ₽ — 150 000 ₽".

4. **Сворачиваемый блок "Рассчитать по сценариям"**
   - Заголовок с иконкой "⌄ / ⌃" (expand/collapse).
   - Внутри: список сценариев (название + диапазон), "+ Добавить".
   - Максимум 5 сценариев в MVP.
   - Переключатель режимов расчёта: "Сумма сценариев" / "По самому дорогому".
   - Вывод: "Рекомендованная цель: X тыс. ₽" + кнопка "Применить рекомендацию".

5. **Применить рекомендацию**
   - При нажатии: поле "Цель подушки" меняется на рекомендованное значение.
   - Порог остаётся как был (либо 30% от старой цели, либо пользовательское значение).
   - После применения: можно отредактировать цель/порог вручную.

### Текстовые подсказки (ненавязчивые)
- Рядом с полем "Минимальный остаток": мини-лейбл "или редактировать" (опциональный намёк).
- Рядом с переключателем режимов: очень мелким текстом "(выбор влияет на рекомендацию)" — только если есть место.

## Календарь (Cashflow Calendar)

### Визуализация порога

1. **Подсветка дней ниже порога**
   - Фон ячейки: очень слабая заливка оранжевого/красного (уважение к контрасту и читаемости).
   - Все дни, где `balance_end_of_day < threshold`, получают эту подсветку.

2. **Маркер первого дня пересечения**
   - На первом дне (в месяце), где баланс < порог, ставится тонкая вертикальная полоска (слева от ячейки) или другой визуальный маркер.
   - Если сегодня уже ниже порога → маркер на сегодняшней ячейке.

3. **Дефицит в ячейке**
   - Для дней ниже порога: вторая строка мелким текстом "−X тыс. ₽".
   - Пример:
     ```
     2026-01-27
     38 000 ₽
     −7 тыс. ₽
     ```

4. **KPI в шапке (верхние карточки месяца)**
   - Рядом с карточкой "Баланс на конец месяца" добавляется вторичная строка только при дефиците:
     ```
     Баланс на конец
     148 001 ₽
     −1 тыс. ₽ до порога
     ```
   - Если всё хорошо → вторая строка не показывается.

### Правила поведения

- При изменении операции / сверке остатков: подсветка автоматически пересчитывается.
- Маркер "пересечения" остаётся одиночным (первый день ниже порога в видимом месяце).
- Если баланс восстановился выше порога → подсветка исчезает, маркер смещается на следующий день-провал (если есть).

---

## Формат чисел и текст

### Округление
- Дефицит в ячейках: округляем до тысяч, формат **"−X тыс. ₽"** (с точкой).
- KPI "до порога": **"−X тыс. ₽ до порога"** (с точкой, с минусом).
- Точные значения: доступны по клику/наведению в полной форме (рубли без сокращений).

### Примеры
- "−7 тыс. ₽" (в ячейке дня)
- "−1 тыс. ₽ до порога" (в KPI шапки)
- "−123 тыс. ₽ до порога" (в KPI шапки, если большой дефицит)

## Acceptance Criteria

### Схема (Configuration Screen)

- [ ] Карточка "Финансовая подушка" отображается на экране настроек.
- [ ] Поле "Цель подушки" редактируемое, обязательное, принимает числа ≥ 0.
- [ ] Поле "Минимальный остаток" по умолчанию = 30% от цели.
- [ ] При изменении цели (до ручного редактирования порога) порог пересчитывается на 30%.
- [ ] После ручного изменения порога автопересчёт отключается для этого пользователя до переиндексации.
- [ ] Прогресс-бар показывает маркер порога (вертикальная полоска).
- [ ] Сворачиваемый блок "Рассчитать по сценариям" видим и может разворачиваться/сворачиваться.
- [ ] В блоке можно добавить 2–5 сценариев (название + min/max суммы).
- [ ] Переключатель режимов расчёта работает: "Сумма" и "По самому дорогому" дают разные рекомендации.
- [ ] Кнопка "Применить рекомендацию" меняет значение "Цель подушки" и сохраняет.
- [ ] После применения рекомендации можно вручную отредактировать цель/порог.

### Календарь (Calendar Screen)

- [ ] Дни с `balance < threshold` подсвечены слабой заливкой (видно, но не кричаще).
- [ ] В каждой подсвеченной ячейке показывается дефицит второй строкой: "−X тыс. ₽".
- [ ] Маркер "пересечения" (вертикальная полоска/иконка) видна на первом дне ниже порога в месяце.
- [ ] Если сегодня уже ниже порога → маркер на сегодне.
- [ ] KPI "Баланс на конец" в шапке календаря дополняется строкой "−X тыс. ₽ до порога" только если есть дефицит.
- [ ] При изменении операции/сверке остатков подсветка пересчитывается корректно.
- [ ] При восстановлении баланса выше порога подсветка исчезает.

### Поведение (Behaviour)

- [ ] Сценарии сохраняются в БД и загружаются при открытии экрана.
- [ ] Пользователь может редактировать название и диапазон сценария.
- [ ] Пользователь может удалить сценарий (минимум 0, максимум 5).
- [ ] Рекомендованная цель считается, но не переписывает "Цель" автоматически — только по клику кнопки.
- [ ] Все числовые поля валидируют ввод (только числа, >= 0, без букв).

### QA & Тестирование

- [ ] Unit-тесты для `SafetyCushionService` (если добавляется отдельный сервис).
- [ ] Integration-тесты: сценарии → рекомендованная цель → применение в UI.
- [ ] Регрессионный тест: календарь пересчитывается при изменении порога.
- [ ] UI-тесты: отображение подсветки дней, маркеров, дефицитов.

## Риски & Миtigations

| Риск | Вероятность | Влияние | Mitigation |
|------|-------------|--------|-----------|
| Пользователь путает "подушку" как отдельный счёт vs концепт порога | Средняя | Среднее | Ясные микро-лейблы ("Минимальный остаток", "Рекомендованная цель") без слова "подушка" в некоторых местах. |
| Большой дефицит (типа −500 тыс. ₽) делает весь месяц "красным" | Низкая | Среднее | Слабая подсветка; дефицит показываем только в ячейках, а не отдельной шкалой. |
| Пользователь ошибочно применяет рекомендацию и не может отменить | Низкая | Высокое | Всегда оставляем возможность ручного редактирования; можно добавить "Отменить" (UNDO) в будущем. |
| Округление до тысяч скрывает важные мелкие разницы | Низкая | Низкое | Точные значения доступны по клику; для MVP достаточно. |
