## Обзор

Финансовая подушка безопасности — это концепция, которая помогает пользователю определить и отслеживать **минимально допустимый остаток денег** для безопасности. Подушка — это не накопительная цель, а скорее **"иметь при себе"**: current_amount вычисляется автоматически как текущий баланс счёта.

**Ключевая идея**: Подушка работает как **пороговая линия в кассовом календаре**, помогая пользователю видеть риски заранее и избегать финансовых провалов.

## Архитектурные решения (ADR)

### D001: Хранение в User, а не как Goal

**Решение:** Настройки подушки хранятся в полях User, а не как отдельный Goal.

**Причины:**
- Подушка **не участвует** в AllocationService (распределении бюджета)
- `current_amount` = текущий баланс (вычисляется автоматически, не накапливается)
- Нет взносов через GoalContribution
- Нельзя удалить (только сбросить)

**Структура данных:**
```python
class User:
    # Существующие поля
    monthly_savings_budget: Decimal
    savings_mode: str
    starting_balance: Decimal

    # Новые поля для подушки
    cushion_target: Decimal = 0           # Целевая сумма (0 = не настроена)
    cushion_threshold: Decimal = 0        # Минимальный порог для календаря
    cushion_threshold_manual: bool = False  # True если порог изменён вручную
```

### D002: Расположение UI — карточка на /goals

**Решение:** Карточка подушки отображается на странице `/goals` в самом верху, над блоком бюджета и накопительными целями.

**Layout /goals:**
```
┌─────────────────────────────────────┐
│ 🛡️ Финансовая подушка              │  ← Виртуальная карточка (из User)
│ Цель: 150 000 ₽  |  Сейчас: 95 000 ₽│
│ [━━━━━━━━━░░░░] 63%                 │
│ [Настроить]                         │
├─────────────────────────────────────┤
│ 💰 Бюджет накоплений: 50 000 ₽/мес  │  ← Существующий блок
├─────────────────────────────────────┤
│ 🎯 Отпуск                           │  ← Обычные Goal
│ 🚗 Машина                           │
└─────────────────────────────────────┘
```

**Настройка через модал** — клик на карточку или кнопку "Настроить" открывает модальное окно.

### D003: Подушка всегда существует

**Решение:** UI всегда показывает карточку подушки, даже если не настроена.

- `cushion_target = 0` → показываем "Настроить подушку" с призывом к действию
- `cushion_target > 0` → показываем прогресс и текущее состояние

**Цель:** Создать понимание важности финансовой подушки у пользователя.

### D004: current_amount = текущий баланс

**Решение:** Прогресс подушки вычисляется автоматически как текущий баланс счёта.

```python
current_amount = CalendarService.get_balance_on_date(user_id, today)
progress = current_amount / cushion_target * 100  # если target > 0
```

**Особенности:**
- Прогресс меняется динамически при изменении баланса
- Нет ручных взносов (GoalContribution не используется)
- Баланс упал → прогресс уменьшился
- Баланс вырос → прогресс увеличился

### D005: Сценарии без БД

**Решение:** Сценарии реализуются как UI-калькулятор без сохранения в БД.

- Пользователь вводит сценарии в модале
- Калькулятор считает рекомендацию
- Пользователь применяет к полю `cushion_target`
- Сценарии **не сохраняются** после закрытия модала

**Причина:** Упрощение MVP. Сохранение сценариев можно добавить позже.

### D006: Нельзя удалить подушку

**Решение:** Запретить удаление. Только "Сбросить настройки" (cushion_target → 0).

После сброса карточка показывает "Настроить подушку" снова.

## Структура данных

### User (новые поля)

```python
class User(Base):
    # ... существующие поля ...

    # Финансовая подушка
    cushion_target = Column(Numeric(10, 2), default=0, nullable=False)
    cushion_threshold = Column(Numeric(10, 2), default=0, nullable=False)
    cushion_threshold_manual = Column(Boolean, default=False, nullable=False)
```

| Поле | Тип | Описание |
|------|-----|----------|
| `cushion_target` | Decimal | Целевая сумма подушки (0 = не настроена) |
| `cushion_threshold` | Decimal | Минимальный порог для календаря (0 = не показывать подсветку) |
| `cushion_threshold_manual` | bool | True если порог изменён вручную (не пересчитывать автоматически) |

### TypedDicts (app/schema/cushion.py)

```python
class CushionSettings(TypedDict):
    """Настройки подушки из User."""
    target: Decimal           # cushion_target
    threshold: Decimal        # cushion_threshold
    threshold_manual: bool    # cushion_threshold_manual
    current_amount: Decimal   # вычисляется (текущий баланс)
    progress: float           # вычисляется (current / target * 100)
    is_configured: bool       # target > 0

class CushionScenario(TypedDict):
    """Сценарий для калькулятора (не сохраняется в БД)."""
    name: str
    min_amount: Decimal
    max_amount: Decimal
```

### UI-Контекст (dcc.Store)

```python
# В модале настройки (временные данные)
cushion-scenarios-store: list[CushionScenario]  # [{name, min_amount, max_amount}, ...]
cushion-calc-mode: str                          # "sum" | "max_scenario"
cushion-recommended: str                        # Decimal as string (JSON-safe)
```

**Важно:** Сценарии живут только в Store пока модал открыт. При закрытии — теряются.

### Edge Cases

| Случай | Поведение |
|--------|-----------|
| `current_amount < 0` (отрицательный баланс) | progress = 0%, показывать как 0 |
| `current_amount > target` | progress = 100% (cap), показывать реальную сумму |
| `target = 0` (не настроена) | Не вычислять progress, показать "Настроить" |
| `threshold > target` | Разрешить (пользователь хочет высокий порог) |
| `threshold = 0, target > 0` | Подсветка в календаре отключена |

## UX: Модал настройки

### Макет

```
┌─────────────────────────────────────────────┐
│ Настройка финансовой подушки            [×] │
├─────────────────────────────────────────────┤
│                                             │
│ Цель подушки                                │
│ ┌─────────────────────────────────────────┐ │
│ │ 150 000                               ₽ │ │
│ └─────────────────────────────────────────┘ │
│                                             │
│ Минимальный остаток на счёте                │
│ ┌─────────────────────────────────────────┐ │
│ │ 45 000                                ₽ │ │
│ └─────────────────────────────────────────┘ │
│ (по умолчанию 30% от цели)                  │
│                                             │
│ ▼ Рассчитать по сценариям                   │
│ ┌─────────────────────────────────────────┐ │
│ │ Сценарий 1: Медицина                    │ │
│ │ от [10 000] до [50 000] ₽          [×]  │ │
│ │                                         │ │
│ │ Сценарий 2: Ремонт авто                 │ │
│ │ от [15 000] до [80 000] ₽          [×]  │ │
│ │                                         │ │
│ │ [+ Добавить сценарий]                   │ │
│ │                                         │ │
│ │ Режим расчёта:                          │ │
│ │ (○) Сумма всех сценариев                │ │
│ │ (●) По самому дорогому                  │ │
│ │                                         │ │
│ │ Рекомендованная цель: 80 000 ₽          │ │
│ │ [Применить]                             │ │
│ └─────────────────────────────────────────┘ │
│                                             │
│ ┌─────────────┐  ┌─────────────────────┐    │
│ │ Сбросить    │  │ Сохранить           │    │
│ └─────────────┘  └─────────────────────┘    │
└─────────────────────────────────────────────┘
```

### Поведение

1. **Цель подушки (input)**
   - Обязательное поле, число ≥ 0
   - При изменении: если `cushion_threshold_manual = False`, пересчитать порог на 30%

2. **Минимальный остаток (input)**
   - По умолчанию = 30% от цели
   - При ручном изменении: установить `cushion_threshold_manual = True`
   - Можно задать любое число ≥ 0

3. **Сценарии (collapsible section)**
   - Максимум 5 сценариев
   - Каждый: название + min_amount + max_amount
   - **Не сохраняются в БД** — только для расчёта рекомендации

4. **Режим расчёта**
   - "Сумма сценариев": `SUM(max_amount)`
   - "По самому дорогому": `MAX(max_amount)`

5. **Применить рекомендацию**
   - Копирует рекомендованную сумму в поле "Цель подушки"
   - Порог пересчитывается если не был изменён вручную

6. **Сбросить**
   - `cushion_target = 0`, `cushion_threshold = 0`, `cushion_threshold_manual = False`
   - Карточка возвращается в состояние "Настроить"

7. **Сохранить**
   - Записывает `cushion_target`, `cushion_threshold`, `cushion_threshold_manual` в User
   - Закрывает модал
   - Триггерит refresh карточки подушки

### Валидация

| Поле | Правило | Сообщение об ошибке |
|------|---------|---------------------|
| Цель подушки | число ≥ 0 | "Введите положительное число" |
| Минимальный остаток | число ≥ 0 | "Введите положительное число" |
| Сценарий: название | не пустое | "Введите название сценария" |
| Сценарий: min_amount | число ≥ 0 | "Введите положительное число" |
| Сценарий: max_amount | число ≥ min_amount | "Максимум должен быть ≥ минимума" |

**Валидация на клиенте** — показывать ошибки inline под полями (dbc.FormFeedback).

### Refresh после сохранения

1. **Модал → Карточка подушки**: callback `update_cushion_card` слушает `cushion-modal-save-trigger`
2. **Карточка → Календарь**: если пользователь перейдёт на /calendar, данные загрузятся свежие
3. **Глобальный trigger не нужен** — подушка не влияет на транзакции

### User ID

В текущей системе используется `user_id = 1` (hardcoded в UI callbacks).
Сервис `SafetyCushionService` принимает `user_id` как параметр для будущей multi-user поддержки.

## Календарь (Cashflow Calendar)

### Условие отображения

Подсветка дней показывается **только если подушка настроена**:
- `cushion_threshold > 0` → показывать подсветку
- `cushion_threshold = 0` → не показывать (подушка не настроена или сброшена)

### Визуализация порога

1. **Подсветка дней ниже порога**
   - CSS класс: `.calendar-day-below-threshold`
   - Фон: слабый оранжевый/персиковый (`rgba(255, 152, 0, 0.15)`)
   - Условие: `balance_end_of_day < cushion_threshold`

2. **Маркер первого дня пересечения**
   - CSS класс: `.calendar-day-threshold-crossed`
   - Визуал: тонкая вертикальная полоска слева (2px, оранжевый)
   - Показывается на **первом** дне в месяце, где баланс < порог

3. **Дефицит в ячейке**
   - Вторая строка мелким текстом: `−X тыс. ₽`
   - Формат: округление до тысяч с точкой
   - Формула: `deficit = cushion_threshold - balance`

   ```
   ┌─────────────┐
   │ 27          │
   │ ↓ ↑         │
   │ 38 000 ₽    │
   │ −7 тыс. ₽   │  ← дефицит до порога
   └─────────────┘
   ```

4. **KPI в шапке календаря**
   - Под карточкой "Баланс на конец месяца"
   - Показывается **только при дефиците** на конец месяца:
   ```
   Баланс на конец
   38 000 ₽
   −7 тыс. ₽ до порога
   ```

### Правила поведения

- При изменении операции / сверке: подсветка пересчитывается
- Маркер "пересечения" — только на первом дне-провале в месяце
- Баланс восстановился → подсветка исчезает с этого дня

### Получение threshold в Calendar

Calendar callback `load_and_navigate_calendar()` должен:
1. Получить `User.cushion_threshold` через `SafetyCushionService.get_settings()`
2. Передать threshold в `build_day_cell()` и `build_stats_cards()`
3. Если `threshold = 0` → не показывать подсветку

**Альтернатива:** Хранить threshold в `calendar-state` Store для избежания лишних запросов к БД.

## Риски & Mitigations

| Риск | Вероятность | Влияние | Mitigation |
|------|-------------|---------|------------|
| Путаница "подушка = накопительная цель" | Средняя | Среднее | Ясные лейблы, отдельная карточка над целями |
| Большой дефицит красит весь месяц | Низкая | Среднее | Слабая подсветка, дефицит только текстом |
| Сценарии теряются при закрытии модала | Средняя | Низкое | Предупреждение перед закрытием (Could Have) |
| current_amount меняется слишком часто | Низкая | Низкое | Обновление только при открытии /goals |
