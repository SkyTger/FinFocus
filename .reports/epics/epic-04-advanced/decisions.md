# Epic-04: Решения (Decisions)

## D001: Quick-add chips — разбивка на два протокола

**Дата**: 2026-01-25
**Статус**: Утверждено

### Контекст
Quick-add chips — это комплексная фича, которую можно разбить на два этапа: чипы категорий (простые) и шаблоны операций (сложные).

### Решение
**Разделить на два протокола:**

**Протокол A: Чипы категорий** (~6-8 дней)
- Дефолтные 5 расход + 2 доход категорий
- Клик на chip → модал создания с предвыбранной категорией
- Пользователь вводит сумму и описание
- UI: плитки с иконками (крупнее чем в Батче 3.2)
- Расположение: страница Transactions, под кнопками "Экспорт" и "Добавить"

**Протокол B: Шаблоны операций** (~6-8 дней)
- Модель Template (name, category_id, amount, description)
- 1-клик создание операции (toast "Отменить" на 3 сек)
- Кастомизация: добавление/удаление/порядок/архивирование
- Управление через "⋯" меню на каждом чипе

### Обоснование
1. **Инкрементальность** — простое (категории) → сложное (шаблоны)
2. **Ранняя ценность** — Протокол A уже дает 70% пользы
3. **Риск-менеджмент** — можно остановиться после A если B окажется сложным
4. **Тестирование** — легче протестировать и исправить баги

### Дефолтные чипы MVP (Протокол A)

**Расход (5 категорий)**:
1. Продукты (icon: `bi-cart`)
2. Дом/Жильё (icon: `bi-house`)
3. Транспорт/Авто (icon: `bi-car-front`)
4. Связь/Коммуналка (icon: `bi-phone`)
5. Развлечения/Кафе (icon: `bi-cup-straw`)

**Доход (2 категории)**:
1. Зарплата (icon: `bi-wallet`)
2. Аванс/Подработка (icon: `bi-cash-coin`)

**КРИТИЧНО**:
- Дефолтные чипы hardcoded в UI для Протокола A
- Протокол B добавит PinnedCategory модель для кастомизации
- Дефолтные чипы станут начальными закрепленными категориями после перехода на PinnedCategory

## D002: Хранение данных — отдельные таблицы вместо JSON

**Дата**: 2026-01-25
**Статус**: Утверждено

### Контекст
Для кастомизации чипов (Протокол B) нужно хранить:
1. Какие категории закреплены (pinned)
2. Шаблоны операций (templates)

Варианты:
- JSON-поле в User модели
- Отдельные таблицы PinnedCategory и Template

### Решение
**Отдельные таблицы**

### Структура

**PinnedCategory** — закрепленные категории для быстрого доступа:
```python
class PinnedCategory(Base):
    id: int
    user_id: int              # FK User
    category_id: int          # FK Category
    sort_order: int           # Порядок отображения
    created_at: datetime
```

**Template** — шаблоны операций с заполненными полями:
```python
class Template(Base):
    id: int
    user_id: int              # FK User
    category_id: int          # FK Category
    amount: Decimal(10,2)     # Сумма операции (может быть None для ручного ввода)
    description: str          # Текст описания
    name: str                 # Название шаблона (например, "Обед в офисе")
    sort_order: int           # Порядок отображения
    is_archived: bool         # Soft delete
    created_at: datetime
```

### Обоснование
1. **Консистентность архитектуры** — все domain entities как таблицы (не JSON)
2. **FK constraints** — гарантия целостности данных через БД
3. **Легко расширять** — добавить поле проще чем менять JSON schema
4. **Запросы** — JOIN проще чем парсинг JSON в SQL
5. **Миграции** — Alembic работает с таблицами, не с JSON структурами

### Trade-offs
- Больше таблиц → больше сложности схемы
- JOIN операции → микро-оверхед по производительности (незначителен для MVP)

**Альтернатива (отклонена)**: JSON-поле `user.pinned_categories` и `user.templates`
- Проще для малых объемов данных
- Проблемы с referential integrity
- Сложнее поддерживать при росте фич

## D003: UX решения для Quick-add chips

**Дата**: 2026-01-25
**Статус**: Утверждено

### Решения по UX

#### 1. Группировка по типам
Чипы разделены на две секции: "Расход" и "Доход"
```
[Расход] Продукты | Дом | Транспорт | Связь | Развлечения | Ещё...
[Доход]  Зарплата | Подработка | Ещё...
```

#### 2. Шаблон 1-клик → toast "Отменить"
```
Клик на шаблон
  ↓
Операция создана мгновенно
  ↓
Toast notification (3 сек):
  "Кофе — 150₽ добавлено [Отменить]"
  ↓
Если клик "Отменить" → удалить операцию
Если timeout → операция остается
```

**КРИТИЧНО**:
- Защита от даблтапа: 0.5-1 сек дебаунс на кнопке
- Операция из шаблона всегда на "сегодня" (date = today)

#### 3. Лимит чипов на экране
- Максимум 2 ряда (7-8 чипов видимых)
- Новые чипы добавляются в начало списка
- Старые уходят в кнопку "Ещё..." (модал с полным списком)

#### 4. Управление чипом (Протокол B)

**Удаление**:
- Hover на чип → появляется крестик (×) в правом верхнем углу
- Альтернатива: "⋯" меню → "Удалить" (архивирование)

**Редактирование шаблона**:
- "⋯" меню → "Изменить" → форма редактирования
- Можно изменить: name, amount, description, category

**Архивирование vs Hard Delete**:
- Удаление шаблона = `is_archived=True` (soft delete)
- Сохраняется история для аналитики
- Можно восстановить через "Архив шаблонов"

#### 5. Изменение порядка чипов (Протокол B)

**Отложено**: Drag-and-drop (сложность высокая)

**MVP решение**:
- Кнопки ↑↓ в "⋯" меню
- Или кнопка "В начало" (sort_order = 1, остальные +1)

#### 6. Визуальное отличие от chips категоризации (Батч 3.2)

**Quick-add chips** (крупнее, плитки):
```
┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ [🛒]        │ │ [🏠]        │ │ [🚗]        │
│ Продукты    │ │ Дом         │ │ Транспорт   │
└─────────────┘ └─────────────┘ └─────────────┘
```

**Категоризация chips** (мелкие, inline):
```
[Еда] [Развлечения] [Транспорт] ...
```

**Отличия**:
- Quick-add: иконка + текст, плитка 100-120px
- Категоризация: только текст, pill-style, 60-80px

#### 7. Расположение на странице

**Страница Transactions**:
```
┌──────────────────────────────────────────────────┐
│ Операции                          [Экспорт] [Добавить] │
├──────────────────────────────────────────────────┤
│ [Расход] 🛒 Продукты | 🏠 Дом | 🚗 Транспорт ... │
│ [Доход]  💼 Зарплата | 💵 Подработка | Ещё...     │
├──────────────────────────────────────────────────┤
│ История операций                                 │
│ ┌──────────────────────────────────────────────┐ │
│ │ 25.01  Расход  -1500₽  Кофейня              │ │
│ └──────────────────────────────────────────────┘ │
```

### Обоснование
- Минимум кликов для частых операций (цель: < 5 сек на операцию)
- Toast notification — знакомый паттерн (Gmail, Slack)
- Архивирование — не теряем данные при "удалении"
- MVP порядок (кнопки ↑↓) вместо сложного drag-and-drop
