# FinFocus: Onboarding Wizard & Balance Alert Toast
## Technical Specification (Batch 4 Advanced Features)

**Дата документа:** 31.01.2026  
**Статус:** Ready for Planning  
**Приоритет:** MUST HAVE  
**Метрика успеха:** Завершение онбординга < 5 минут; пропуск wizard'а не должен привести к потере доверия

---

## 1. Обзор фичи

При первом входе в FinFocus пользователь видит блокирующий мини-wizard (2 шага) для настройки:
1. **Шаг 1:** Ввод стартового баланса (обязателен для продолжения, но можно пропустить)
2. **Шаг 2:** Имя пользователя и аватар (полностью опционально)

Если стартовый баланс не задан, на дашборде показывается **предупреждающий toast** (полупрозрачный жёлтый), который можно закрыть навсегда.

### Ценность
- Стартовый баланс — критичен для корректного расчёта cash calendar; без него все прогнозы некорректны
- Низкое трение при входе: можно пропустить и посмотреть продукт, но с явным предупреждением
- Путь исправления через "Календарь → Сверка" хорошо интегрирует с существующей функцией reconciliation

### 2.2. Шаг 1: Стартовый баланс

**Заголовок:** "Добро пожаловать"  
**Подзаголовок/Label:** "Стартовый баланс на сегодня"

**Ввод:**
- Тип: `<input type="number" />` или подобное
- Формат: читает число, отображает с форматированием (пробелы для тысяч)
- Суффикс: "₽" (рубль) — в поле или справа от него
- Плейсхолдер: "0"
- Max значение: логический лимит (e.g., 999,999,999)

**Валидация:**
- Пустое поле = некорректно, primary CTA **disabled**
- Отрицательное число = разрешаем (кейс "долг"), но можно добавить warning позже (в Batch 5)

**Подсказка (под полем):**  
"Нужен для точного прогноза. Можно настроить позже в Календаре → "Сверка"."

**CTA кнопки:**
1. **Primary (зелёный):** "Продолжить"  
   - Enabled только если balance > '' (не пусто) или balance !== null
   - Действие: save `starting_balance`, перейти на шаг 2
   - Hover: darker green, cursor pointer
   - Focus: outline (фирменный цвет фокуса)

2. **Secondary (текстовая, #0e2a47):** "Пропустить"  
   - Всегда enabled
   - Действие: пропустить шаг 2, закрыть wizard, показать toast на дашборде
   - Цвет текста: #0e2a47

**Поведение:**
- Пользователь видит индикатор "Шаг 1 из 2" или 2 точки (первая активная)
- Если нажать "Пропустить" на шаге 1 → wizard закрывается, дашборд показывается с toast'ом

### 2.3. Шаг 2: Имя & Аватар

**Условие отображения:**
- Только если пользователь нажал "Продолжить" на шаге 1
- Если нажал "Пропустить" на шаге 1 → прямо на дашборд

**Заголовок:** "Как вас называть?" (или "Ваше имя")

**Ввод имени:**
- Тип: `<input type="text" />`
- Плейсхолдер: "Введите имя (необязательно)"
- Max длина: 50 символов
- Валидация: нет (полностью опционально)

**Сетка аватаров:**
- 8–12 аватаров в сетке (2–4 на мобилке, 4+ на десктопе)
- Выбор по клику (переключение активного состояния)
- По умолчанию: первый аватар выбран (или без выбора, если предпочитаем)
- Стиль: все аватары одинакового размера (e.g., 64px), чистые иконки/буквы

**CTA кнопки:**
1. **Primary (зелёный):** "Готово"  
   - Всегда enabled (даже если имя пусто)
   - Действие: save `username` (если не пусто) и `avatar_id`, закрыть wizard, показать дашборд
   - Перейти на дашборд

2. **Secondary (текстовая, #0е2a47):** "Сделать позже"  
   - Всегда enabled
   - Действие: закрыть wizard БЕЗ сохранения имени/аватара, показать дашборд
   - Имя и аватар можно настроить позже в "Настройки"

**Поведение:**
- Индикатор "Шаг 2 из 2" (вторая точка активна)
- Это финальный шаг; на дашборде появляется только toast (если баланс не задан)

## 3. Toast: Предупреждение о стартовом балансе

### 3.1. Визуальная структура

**Условие показа:**
- На дашборде, если `starting_balance == NULL`
- Показывается в момент загрузки дашборда или после пропуска wizard'а
- Тип компонента: **Toast** (не банер, не alert — сообщение с действием)

**Позиция:** Верх дашборда (или top-right corner, в зависимости от обычного места toast'ов в FinFocus)

**Визуал:**
```
┌────────────────────────────────────────────────────────┐
│  ⚠️ Не задан стартовый баланс — прогноз может быть  │  [✕]
│     некорректным. Укажите его (Календарь → "Сверка"). │
│                                                        │
│                          [Сверить баланс]             │
└────────────────────────────────────────────────────────┘
```

**Цвет & стиль:**
- Фон: жёлтый полупрозрачный (`rgba(255, 193, 7, 0.15)` или подобный light yellow)
- Текст: тёмный (#0e2a47 или default text color)
- Граница: лёгкая жёлтая граница (1px)
- Паддинг: 16px (вверх/вниз), 20px (влево/вправо)

**Кнопки:**
1. **CTA (primary зелёный):** "Сверить баланс"  
   - Действие: открыть "Календарь" → сразу на "Сверку" (если это separate modal/section)
   - Или перейти на вкладку "Календарь" с открытой сверкой

2. **Закрытие (✕ крестик):**  
   - Справа сверху в toast'е
   - Действие: скрыть toast **навсегда** (до конца сессии или перезагрузки приложения)
   - Хранить флаг: `onboarding_balance_toast_dismissed == True` (в localStorage или дб user session)

### 3.2. Поведение

**Показ:**
- Toast появляется при загрузке дашборда, если `starting_balance == NULL` и ранее он не был закрыт никаким из возможных способов

**Закрытие:**
- Нажатие крестика: toast больше не показывается при перезагрузке
- Нажатие CTA "Сверить баланс": toast закрывается, переходим в Календарь, toast не появляется пока идёт сессия

**Исчезновение:**
- Если пользователь установил `starting_balance` (через Сверку или другую форму), toast **автоматически исчезает** и не показывается в следующем входе

**Auto-dismiss:** Не нужен; пользователь закрывает сам или переходит в Сверку

## 4. Acceptance Criteria

### Шаг 1: Стартовый баланс
- [ ] При первом входе показывается wizard с оверлеем (мягкий, не чёрный)
- [ ] Карточка центрирована, текст читабелен, поле ввода крупное
- [ ] "Продолжить" disabled, пока поле пусто; enabled при любом числе (в том числе 0)
- [ ] "Пропустить" всегда enabled
- [ ] Нажатие "Продолжить" → сохранение баланса, переход на шаг 2
- [ ] Нажатие "Пропустить" → закрытие wizard, дашборд + toast

### Шаг 2: Имя & аватар
- [ ] Показывается только если пользователь нажал "Продолжить" на шаге 1
- [ ] Имя: опционально, max 50 символов
- [ ] Аватары: 8–12 штук, выбираемые (toggle selection)
- [ ] "Готово" всегда enabled
- [ ] "Сделать позже" всегда enabled
- [ ] Оба действия закрывают wizard и ведут на дашборд
- [ ] После шага 2 `first_launch = False`

### Toast на дашборде
- [ ] Toast показывается сверху дашборда, если `starting_balance == NULL` и `onboarding_balance_toast_dismissed == False`
- [ ] Жёлтый полупрозрачный фон, текст читабелен
- [ ] CTA "Сверить баланс" → переход в Календарь с открытой сверкой
- [ ] Крестик [✕] → скрывает toast навсегда (флаг `onboarding_balance_toast_dismissed = True`)
- [ ] После установки `starting_balance` toast не показывается

### Общее
- [ ] Весь процесс (шаг 1 + шаг 2) занимает < 5 минут
- [ ] Нет потери данных при закрытии браузера во время wizard'а
- [ ] Пропуск wizard'а не破ит прогноз (cash calendar показывает нули/warning, но не крашится)
- [ ] Цветовая палитра: зелёный (primary CTA), #0e2a47 (заголовки/secondary), жёлтый (toast)

## 6. Риски & Mitigations

| Риск | Mitigation |
|------|-----------|
| Пользователь пропускает wizard, потом видит нулевой баланс и думает, что app "не работает" | Toast с явным CTA + предупреждение о некорректности прогноза |
| Слишком много шагов → отскок | MVP: только 2 шага, оба быстрые (~30 сек на шаг 1, опционально шаг 2) |
| Toast раздражает → пользователь закрывает и забывает | "Закрыть навсегда" даёт контроль; но если потом установит баланс, toast исчезнет автоматически |
| Обновление стиля app ломает wizard | Токены цветов/типографики выделены отдельно, легко обновить |
| На мобилке wizard не помещается | Использовать responsive design, проверить на экранах 375px+ |
