**Epic**: Epic-04: Advanced Features
**Дата создания**: 2026-02-01
**Статус**: Планируется
**Зависимости**: Батч 3.1 (Категории), Батч 2 (Multiple Goals with Priorities)

## 1. Описание фичи

### Бизнес-ценность

Пользователи не понимают, как бюджет накоплений влияет на реальный баланс в календаре. Им нужна визуализация: "Когда я откладываю деньги на цели, как это отражается в кассовом плане?"

Эта фича решает проблему разрыва между планированием накоплений (страница Goals) и кассовым планированием (страница Calendar).

### Суть

Интеграция месячного бюджета накоплений (`monthly_savings_budget`) с кассовым календарём через два режима работы:

- **Режим 1: "Дата указана"** — пользователь фиксирует дату резервирования бюджета (например, 5-е число каждого месяца)
- **Режим 2: "Из остатка"** — пользователь резервирует деньги на конкретную цель по факту наличия средств

### Философия

**Бюджет и подушка — это НЕ расходы, а "состояние кармана":**

- Бюджет накоплений — это не вычитание из баланса, а требование к наличию средств
- Подушка безопасности — это готовность к неожиданностям
- В календаре должно быть видно: "У меня есть X рублей для целей" или "Я отложил X на конкретную цель"

**Динамический бюджет:**

```
доступный_бюджет = monthly_savings_budget - сумма_взносов_в_этом_месяце
```

Бюджет уменьшается при каждом взносе в цель.

## 2. User Stories

### US-1: Фиксированная дата резервирования бюджета

**Как** пользователь,
**Я хочу** зафиксировать дату резервирования бюджета накоплений (например, 5-е число),
**Чтобы** в календаре отражалась одна операция на всю сумму бюджета и я мог планировать распределение по целям.

**Acceptance Criteria:**
- ✅ В настройках страницы Goals есть поле "Дата резервирования" (день месяца, 1-31)
- ✅ В календаре на указанную дату каждого месяца отображается виртуальная recurring операция "Резерв на цели"
- ✅ Сумма операции = `monthly_savings_budget` (не меняется при взносах)
- ✅ При нажатии "Внести взнос" в карточке цели:
  - Операция в календаре НЕ создаётся
  - Только учёт распределения (GoalContribution)
  - Доступный бюджет уменьшается
- ✅ На странице Goals видно: "X₽ из Y₽ распределено в этом месяце"
- ✅ Остаток баланса в календаре НЕ меняется при внесении взноса (т.к. деньги уже зарезервированы 5-го числа)

---

### US-2: Резервирование из остатка

**Как** пользователь,
**Я хочу** вносить взносы в цели по факту наличия средств (без фиксированной даты),
**Чтобы** гибко управлять накоплениями и видеть в календаре конкретные операции по целям.

**Acceptance Criteria:**
- ✅ В настройках страницы Goals поле "Дата резервирования" не заполнено (по умолчанию)
- ✅ В календаре НЕТ фиксированной операции "Резерв на цели"
- ✅ При нажатии "Внести взнос" в карточке цели:
  - Создаётся операция в календаре на сегодняшнюю дату
  - Название операции: "Взнос: {название цели}"
  - Тип: специальный тип (НЕ expense, НЕ transfer)
  - Запись в GoalContribution
  - Доступный бюджет уменьшается
- ✅ В календаре видно N операций (по одной на каждый взнос)
- ✅ Остаток баланса в календаре уменьшается на сумму взноса
- ✅ На странице Goals видно: "X₽ из Y₽ внесено в этом месяце"

---

### US-3: Переключение между режимами

**Как** пользователь,
**Я хочу** переключаться между режимами "Дата указана" и "Из остатка",
**Чтобы** выбрать удобную для меня стратегию накоплений.

**Acceptance Criteria:**
- ✅ В модале настройки бюджета есть переключатель режимов:
  - "Фиксированная дата" (показать поле выбора дня месяца)
  - "Из остатка" (скрыть поле даты)
- ✅ При переключении с "Из остатка" на "Фиксированную дату":
  - Существующие операции "Взнос: цель" НЕ удаляются
  - Создаётся recurring операция "Резерв на цели" с текущего месяца
  - История взносов сохраняется
- ✅ При переключении с "Фиксированной даты" на "Из остатка":
  - Recurring операция "Резерв на цели" помечается как завершённая
  - Существующие взносы остаются в истории
  - Новые взносы создают операции в календаре
- ✅ Календарь автоматически обновляется после изменения режима

---

### US-4: Визуализация прогресса бюджета

**Как** пользователь,
**Я хочу** видеть прогресс использования бюджета накоплений,
**Чтобы** понимать, сколько ещё могу отложить в этом месяце.

**Acceptance Criteria:**
- ✅ На странице Goals есть карточка/секция "Бюджет накоплений этого месяца":
  - "Распределено: X₽ из Y₽" (для режима "Дата указана")
  - "Внесено: X₽ из Y₽" (для режима "Из остатка")
  - Прогресс-бар с визуальной индикацией:
    - 0-70%: зелёный
    - 70-90%: жёлтый
    - 90-100%: оранжевый
    - >100%: красный (перерасход)
- ✅ При превышении бюджета (X > Y):
  - НЕТ блокировки взносов
  - НЕТ предупреждений (не давить на пользователя)
  - Только визуальная индикация (красный цвет)
- ✅ Автообновление при внесении взноса

## 3. UI/UX Requirements

### 3.1. Goals Page — Настройка режима

**Локация**: Модал настройки бюджета (существующий "Настроить бюджет")

**Добавить блок:**

```
┌─────────────────────────────────────────┐
│ Режим резервирования                    │
├─────────────────────────────────────────┤
│ ◉ Фиксированная дата                    │
│   Резервировать: [▼ 5] числа каждого    │
│                      месяца             │
│                                         │
│ ○ Из остатка                            │
│   Резервировать деньги при внесении     │
│   взноса в конкретную цель              │
└─────────────────────────────────────────┘
```

**Элементы:**
- Radio buttons для выбора режима
- Dropdown для выбора дня (1-31) — активен только в режиме "Фиксированная дата"
- Hint текст: "В режиме 'Фиксированная дата' бюджет резервируется на календаре как одна операция. В режиме 'Из остатка' — создаются отдельные операции при каждом взносе."

**Вариант 2 (режим "Из остатка"):**

### 3.3. Calendar Page — Операция "Резерв на цели"

**Режим "Фиксированная дата":**

В календаре на указанную дату каждого месяца:

```
┌──────────┐
│ 5 января │  ← фиксированная дата
├──────────┤
│ 💼 Резерв на цели │  ← иконка кошелька
│ -30 000 ₽│  ← сумма monthly_savings_budget
│          │
│ Остаток: │
│ 45 000 ₽ │
└──────────┘
```

**Визуальные особенности:**
- Иконка: 💼 (кошелёк/копилка)
- Цвет: нейтральный (не зелёный/красный, т.к. это не доход/расход)
- Tooltip при hover: "Резерв на накопительные цели. Распределено: X₽ из 30 000₽"
- НЕТ возможности редактировать вручную (системная операция)

**Режим "Из остатка":**

В календаре на дату внесения взноса:

```
┌──────────┐
│ 12 января│  ← дата внесения взноса
├──────────┤
│ 🎯 Взнос: Ремонт │  ← иконка цели + название
│ -5 000 ₽ │  ← сумма взноса
│          │
│ Остаток: │
│ 40 000 ₽ │
└──────────┘
```

**Визуальные особенности:**
- Иконка: 🎯 (цель)
- Цвет: нейтральный
- Tooltip: "Взнос в цель 'Ремонт'. Осталось до цели: X₽"
- Можно редактировать (изменить сумму взноса)

**Текущее состояние** (карточка цели):

```
┌─────────────────────────────────┐
│ 🏠 Ремонт                        │
│                                 │
│ Цель: 100 000 ₽                 │
│ Собрано: 35 000 ₽ (35%)        │
│                                 │
│ [Внести взнос]                  │  ← существующая кнопка
└─────────────────────────────────┘
```

**После клика "Внести взнос"** → открывается модал:

```
┌────────────────────────────────────────┐
│ Внести взнос в цель "Ремонт"           │
├────────────────────────────────────────┤
│ Сумма взноса:                          │
│ [_________] ₽                          │
│                                        │
│ Доступный бюджет: 15 000 ₽             │  ← динамический бюджет
│                                        │
│ [Отмена]              [Внести]        │
└────────────────────────────────────────┘
```

**Валидация:**
- ❌ НЕТ блокировки при превышении доступного бюджета
- ⚠️ Warning при превышении: "Вы превысите месячный бюджет на X₽"
- ❌ НЕТ блокировки при превышении оставшейся суммы цели
- ⚠️ Warning: "Сумма взноса превышает оставшуюся часть цели"

**После подтверждения:**
- Режим "Дата указана":
  - GoalContribution создаётся
  - Операция в календаре НЕ создаётся
  - Карточка бюджета обновляется: "Распределено: 20 000 ₽ из 30 000 ₽"
  - Toast: "Взнос 5 000 ₽ учтён. Осталось распределить: 10 000 ₽"

- Режим "Из остатка":
  - GoalContribution создаётся
  - Операция "Взнос: Ремонт" создаётся в календаре (на сегодня)
  - Карточка бюджета обновляется: "Внесено: 13 500 ₽ из 30 000 ₽"
  - Календарь обновляется (остаток уменьшается)
  - Toast: "Взнос 5 000 ₽ внесён. Осталось внести: 16 500 ₽"

## 4. Scope и ограничения MVP

### В scope MVP:

- ✅ Два режима работы бюджета (фиксированная дата / из остатка)
- ✅ Переключение между режимами через модал настроек
- ✅ Визуализация прогресса бюджета на Goals странице
- ✅ Операция "Резерв на цели" в календаре (режим 1)
- ✅ Операции "Взнос: цель" в календаре (режим 2)
- ✅ Динамический расчёт доступного бюджета
- ✅ Учёт взносов при расчёте "X из Y"

### Вне scope MVP (в Backlog):

- ❌ Перенос недовнесённого бюджета на следующий месяц
- ❌ Работа с остатками при превышении нужных сумм
- ❌ Предупреждения о недостатке средств для выполнения плана
- ❌ Автоматическое распределение остатка бюджета в конце месяца
- ❌ История изменений режима (аудит)
- ❌ Интеграция с подушкой безопасности (умное распределение остатков)
- ❌ Уведомления "Пора вносить взнос" (для режима "Из остатка")

## 5. Открытые вопросы

### 5.1. Что делать с существующими взносами при переключении режима?

**Вопрос**: Пользователь работал в режиме "Из остатка", создал 3 взноса (3 операции в календаре). Затем переключился на "Фиксированная дата". Что происходит с этими 3 операциями?

**Предложенное решение** (для спецификации):
- Операции остаются в календаре (history preservation)
- Recurring операция "Резерв на цели" создаётся с текущего месяца
- Учёт: "Распределено: X₽" = сумма ВСЕХ взносов (включая старые операции)
- Т.е. история не теряется, но новые взносы работают по новому режиму

### 5.2. Как обрабатывать месяцы с меньшим количеством дней?

**Вопрос**: Пользователь выбрал "31-е число". Что происходит в феврале (28/29 дней)?

**Предложенное решение** (Anchored-алгоритм):
- Использовать Anchored-алгоритм из RecurringService
- 31-е число → последний день месяца (28/29/30/31)
- Аналогично recurring транзакциям

### 5.3. Как показывать бюджет на границе месяцев?

**Вопрос**: Сегодня 30 января, пользователь открывает Goals. Какой месяц показывать в карточке бюджета?

**Предложенное решение**:
- Показывать текущий месяц (январь)
- В календаре видны операции прошлых и будущих месяцев
- Карточка бюджета = snapshot текущего месяца
- Возможность переключения периода (dropdown "Январь 2026 ▼") — опционально

### 5.4. Можно ли удалять операцию "Резерв на цели"?

**Вопрос**: Пользователь случайно кликнул на операцию "Резерв на цели" в календаре. Что произойдёт?

**Предложенное решение**:
- Операция "Резерв на цели" — read-only (системная)
- Клик → tooltip с объяснением: "Эта операция создаётся автоматически на основе настроек бюджета. Для изменения перейдите в настройки на странице Цели."
- НЕТ модала редактирования
- НЕТ возможности удаления вручную

## 6. Связь с другими фичами

### 6.1. Финансовая подушка безопасности (Батч 4.2)

**Текущее состояние**: Подушка реализована как поля в User (cushion_target, cushion_threshold_percent).

**Потенциальная интеграция** (post-MVP):
- Если `доступный_бюджет > 0` в конце месяца → предложить направить остаток на подушку
- "У вас осталось 5 000 ₽ неосвоенного бюджета. Направить на финансовую подушку?"
- Автоматическое создание ADJUSTMENT транзакции

**Для MVP**: интеграции НЕТ, работают независимо.

### 6.2. Категории операций (Батч 3.1)

**Вопрос**: Нужна ли категория для операций "Взнос: цель"?

**Решение**:
- Операция "Взнос: цель" НЕ ИМЕЕТ категории (category_id = NULL)
- Аналогично TRANSFER и ADJUSTMENT
- Причина: это не расход, а перемещение средств в целевой "карман"

### 6.3. Recurring Transactions (Батч 2)

**Связь**: Операция "Резерв на цели" в режиме "Фиксированная дата" — это recurring операция.

**Переиспользование**:
- Использовать RecurringService для создания виртуальных экземпляров
- Anchored-алгоритм для обработки коротких месяцев
- НО: специальный тип (не INCOME/EXPENSE/TRANSFER)

## 7. Метрики успеха

### Продуктовые метрики:

- **Adoption rate**: > 60% пользователей выбирают режим резервирования (не оставляют по умолчанию)
- **Режим "Дата указана"**: > 40% пользователей используют
- **Режим "Из остатка"**: > 20% пользователей используют
- **Engagement**: количество взносов в месяц увеличивается на 25%

### UX метрики:

- **Time to first contribution**: < 2 минуты после настройки режима
- **Confusion rate**: < 10% пользователей переключают режим более 2 раз (индикатор непонимания)
- **Satisfaction**: "Понятно ли отображение бюджета в календаре?" — > 80% "да"

### Технические метрики:

- Время загрузки календаря с операцией "Резерв на цели": < 1.5 сек
- 0 критических багов с расчётом доступного бюджета
