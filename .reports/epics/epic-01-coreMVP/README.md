# Epic 01: Core MVP

## 🎯 Цель

Создать минимально жизнеспособную версию (MVP) приложения FinFocus с базовым функционалом для планирования личного и семейного бюджета. Пользователи должны иметь возможность вручную добавлять финансовые операции, видеть остатки по дням в кассовом календаре и отслеживать прогресс одной накопительной цели.

## 📊 Scope

### Входит в эпик:

**Управление операциями**:
- Ручное добавление доходов и расходов с указанием даты
- Просмотр списка операций (базовый функционал)
- Редактирование и удаление операций

**Кассовый календарь**:
- Отображение остатков денежных средств по дням
- Визуализация будущих поступлений и списаний
- Расчет кумулятивных остатков на основе операций

**Dashboard (дашборд)**:
- Карточки с ключевыми показателями (доходы, расходы, остаток)
- Графики Plotly для визуализации данных
- Фильтры по периодам (месяц/год)

**Накопительные цели**:
- Создание одной активной цели с целевой суммой и датой
- Автоматический расчет ежемесячных взносов
- Отображение прогресса выполнения цели
- Ручное добавление взносов в цель

### Не входит в эпик:

- Повторяющиеся операции (зарплата, платежи) → Батч 2
- Множественные цели с приоритетами → Батч 2
- Режимы накоплений (свободный/средний/строгий) → Батч 2
- Категоризация операций → Батч 3
- Графики динамики и структуры расходов → Батч 3
- Финансовая подушка безопасности → Батч 4
- Импорт банковских выписок → Батч 4
- AI-рекомендации, интеграции с банками → Won't Have

## ✅ Критерии успеха

### Функциональные критерии:
- [ ] Пользователь может добавить доход/расход с датой и описанием
- [ ] Кассовый календарь корректно отображает остатки по дням
- [ ] Dashboard показывает актуальные показатели за выбранный период
- [ ] Пользователь может создать одну накопительную цель
- [ ] Система автоматически рассчитывает ежемесячные взносы
- [ ] Пользователь может добавить взнос в цель
- [ ] Прогресс цели отображается визуально (прогресс-бар)

### Технические критерии:
- [ ] Unit тесты покрывают критический функционал (≥80%)
- [ ] Время загрузки календаря < 2 сек
- [ ] Валидация данных на стороне клиента и сервера
- [ ] Обработка ошибок с понятными сообщениями

### Качественные критерии:
- [ ] Интерфейс интуитивен для первого использования
- [ ] Мобильная адаптивность работает на устройствах 320px+
- [ ] Код соответствует стандартам проекта (flake8, black)

## 📈 Ключевые метрики

### Пользовательские метрики:
- Время до добавления первой операции < 2 минуты
- Время до создания первой цели < 10 минут
- Понимание кассового календаря без инструкций ≥ 70%

### Технические метрики:
- Покрытие тестами ≥ 80%
- Время загрузки Dashboard < 3 сек
- Время отклика операций < 500ms

## 🚨 Риски и предположения

### Риски:
- **Средний**: Сложность расчета кассового календаря с учетом будущих операций
- **Низкий**: Производительность Plotly графиков при большом количестве операций
- **Низкий**: Пользовательское принятие концепции целевого бюджетирования

### Стратегии митигации:
- Ранние прототипы движка расчета с юнит-тестами
- Оптимизация Plotly графиков с lazy loading
- Непрерывная валидация через пользовательские интервью

### Предположения:
- Пользователи готовы вручную вводить операции в MVP версии
- SQLite достаточно для разработки и тестирования
- Одной накопительной цели достаточно для валидации концепции
- Пользователи понимают концепцию кассового планирования
