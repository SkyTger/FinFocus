## 🎯 Цель и контекст

### Цель эпика
Переделать Dashboard по новой UI/UX спецификации от продуктовой команды — улучшить читаемость метрик, добавить дневной график кассового календаря, унифицировать цветовую схему и формат денег по всему приложению.

### Контекст проекта
FinFocus — веб-приложение для планирования бюджета (Python 3.12 + Dash 2.17.1 + Plotly + Bootstrap). Проект прошел батчи 0-4 (483 теста), реализовано:
- Кассовый календарь (протокол 0002-calendar-service)
- Dashboard с KPI и графиками (протокол 0003-dashboard-service)
- Цели с распределением бюджета (протоколы 0006-0009)
- Категоризация и аналитика (протоколы 0010-0011)
- Wishlist и Safety Cushion (протоколы 0013, 0020)

**Проблема**: Текущий Dashboard не соответствует новым требованиям к UX (дневной детализации, цветам, формату денег).

## 💡 Ключевые решения из обсуждения

### 1. Тёмная тема — откладывается
- **Решение**: Реализация тёмной темы выносится в отдельную задачу после MVP
- **Обоснование**: Desktop-first, светлая тема достаточна для MVP
- **Действие**: Внести в ROADMAP как отдельный эпик Epic-06-Dark-Theme

### 2. Формат денег ₽ — глобальное изменение
- **Решение**: Меняем формат денег с `$X,XXX.XX` на `X XXX ₽` **везде** в приложении
- **Обоснование**: Единый стандарт по спецификации, российская локализация
- **Затронуто**: `app/utils/formatters.py` + все UI-компоненты (Dashboard, Calendar, Goals, Transactions)
- **Формат**:
  - Положительные: `15 000 ₽`
  - Отрицательные: `−2 500 ₽` (знак минус обязателен, цвет красный)
  - Дельта: `+2 350 ₽` (зелёный) / `−1 200 ₽` (красный)

### 3. Дневной график — отдельный метод
- **Решение**: Создать `DashboardService.get_daily_cashflow()` — не переиспользовать CalendarService напрямую
- **Обоснование**: Оптимизация производительности (dashboard должен "летать"), разделение concerns
- **Детали**:
  - CalendarService — детальная логика для календаря с recurring, exceptions
  - DashboardService — агрегация для графиков без лишних расчётов

### 4. AI Assistant и Exchange — скрыть, не удалять
- **Решение**: Скрыть карточки AI Assistant и Exchange с Dashboard (display:none или убрать из layout)
- **Обоснование**: Фичи планируются к реализации позже, код сохраняем
- **Действие**: Закомментировать вызовы в `app/components/dashboard.py`, добавить TODO

### 5. Сайдбар — Вариант A (обернуть содержимое)
- **Решение**: Обернуть содержимое `app/components/sidebar.py` в `dbc.Card`, добавить стили
- **Обоснование**: Не трогаем layout в `main.py`, минимальные изменения
- **Детали**:
  - Фон карточки: `#ffffff` (светлая тема)
  - Бордер: `1px solid #bdc3c7` или тень `0 2px 8px rgba(0,0,0,0.08)`
  - Активный пункт: зелёный бордер/иконка (`#2ecc71`)

### 6. Адаптивность — desktop-first
- **Решение**: Базовые breakpoints только если не усложняют
- **Обоснование**: MVP фокус на desktop (1440px+), mobile — будущий эпик
- **Breakpoints**:
  - 768px: сайдбар сужается или скрывается
  - 576px: KPI horizontal scroll, 2-колонка в single-column

### 7. Пустые состояния — часть работы над таблицами
- **Решение**: Реализовать empty states с иконкой + текст + CTA "Добавить"
- **Обоснование**: Улучшение UX при отсутствии данных
- **Затронуто**: "Недавние операции" и "Предстоящие операции" таблицы
