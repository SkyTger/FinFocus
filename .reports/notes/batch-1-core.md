# Батч 1: Core MVP

**Продолжительность**: 4 недели  
**Тип**: Delivery (полноценная разработка)  
**Цель**: Создать минимально жизнеспособную версию с базовым функционалом

## Обоснование приоритета

Батч 1 реализует основу приложения согласно MoSCoW приоритизации - Must Have функции. Кассовый календарь с операциями и одна накопительная цель составляют уникальную ценность продукта. Этого достаточно для валидации гипотез о пользовательской ценности и получения первой обратной связи от реальных пользователей.

## Пользовательские истории (Must Have)

### Epic 1: Управление финансовыми операциями
- **US-1.1**: Как пользователь, я могу добавить доход с указанием суммы, даты и описания
- **US-1.2**: Как пользователь, я могу добавить расход с указанием суммы, даты и описания  
- **US-1.3**: Как пользователь, я могу редактировать и удалять созданные операции
- **US-1.4**: Как пользователь, я вижу список всех операций с возможностью сортировки по дате

### Epic 2: Кассовый календарь
- **US-2.1**: Как пользователь, я вижу календарь с отмеченными датами доходов и расходов
- **US-2.2**: Как пользователь, я вижу рассчитанный остаток средств на каждую дату
- **US-2.3**: Как пользователь, я могу добавить операцию прямо из календаря кликом по дате
- **US-2.4**: Как пользователь, я могу переключаться между месяцами и видеть операции в будущем

### Epic 3: Дашборд
- **US-3.1**: Как пользователь, я вижу общие показатели: доходы, расходы, остаток за текущий месяц
- **US-3.2**: Как пользователь, я могу переключить вид с месячного на годовой  
- **US-3.3**: Как пользователь, я вижу простой график динамики доходов и расходов
- **US-3.4**: Как пользователь, я вижу разность доходов и расходов (профицит/дефицит)

### Epic 4: Накопительная цель  
- **US-4.1**: Как пользователь, я могу создать цель с названием, суммой и целевой датой
- **US-4.2**: Как пользователь, система рассчитывает и показывает необходимый ежемесячный взнос
- **US-4.3**: Как пользователь, я вижу прогресс накоплений к цели в процентах и абсолютных величинах
- **US-4.4**: Как пользователь, я могу вручную отметить взнос в цель

## Техническая архитектура

### Backend (Node.js + Express)
```
/src
  /models
    - Transaction.js (операции)  
    - Goal.js (цели)
    - User.js (пользователи)
  /services
    - CashFlowService.js (расчёт остатков)
    - GoalService.js (расчёт взносов)
  /controllers
    - TransactionController.js
    - GoalController.js
  /routes
    - api/transactions
    - api/goals
    - api/dashboard
```

### Frontend (React)
```
/src
  /components
    /Dashboard
      - OverviewCards.jsx
      - CashFlowChart.jsx
    /Calendar  
      - CalendarView.jsx
      - TransactionModal.jsx
    /Goals
      - GoalCard.jsx
      - CreateGoalForm.jsx
    /Common
      - Header.jsx
      - Sidebar.jsx
  /services
    - api.js (HTTP клиент)
  /utils
    - dateHelpers.js
    - currencyFormatter.js
```

### База данных (PostgreSQL)
```sql
-- Основные таблицы
users (id, email, created_at)
transactions (id, user_id, amount, date, type, description)  
goals (id, user_id, name, target_amount, target_date, current_amount)

-- Индексы для производительности
CREATE INDEX idx_transactions_user_date ON transactions(user_id, date);
CREATE INDEX idx_goals_user ON goals(user_id);
```

## План разработки по неделям

### Неделя 1: Backend основа + API
**Разработчики**: 2 backend

**Задачи**:
- Настройка проекта: Node.js + Express + PostgreSQL
- Модели данных и миграции БД
- CRUD API для операций (transactions)
- Базовые валидации и обработка ошибок
- Unit тесты для сервисов

**Критерии готовности**:
- API endpoints работают согласно OpenAPI спецификации
- Покрытие тестами > 80% для бизнес-логики
- Документация API (Swagger/Postman)

### Неделя 2: Frontend основа + Dashboard  
**Разработчики**: 2 frontend

**Задачи**:
- Создание React приложения с роутингом
- Базовые компоненты UI (Header, Sidebar)
- Dashboard с карточками показателей
- Интеграция с backend API для операций
- Адаптивная вёрстка для мобильных устройств

**Критерии готовности**:
- Dashboard корректно отображает данные из API
- UI адаптируется под экраны 320px-1920px
- Обработка состояний загрузки и ошибок

### Неделя 3: Кассовый календарь
**Разработчики**: 1 backend + 2 frontend

**Задачи Backend**:
- CashFlowService: расчёт остатков по датам
- API endpoint для календарных данных
- Оптимизация запросов для быстрого расчёта месяца

**Задачи Frontend**:  
- Компонент календаря с визуализацией операций
- Модальные окна для добавления/редактирования операций
- Отображение рассчитанных остатков на датах
- Навигация между месяцами

**Критерии готовности**:
- Календарь загружается < 2 сек для 100+ операций
- Корректный расчёт остатков для любых дат в пределах года
- Интуитивное добавление операций из календаря

### Неделя 4: Накопительные цели + Интеграция
**Разработчики**: 1 backend + 1 frontend + 1 QA

**Задачи Backend**:
- Модель и API для целей накоплений  
- GoalService: расчёт необходимых взносов
- Интеграция целей с кассовым календарём

**Задачи Frontend**:
- Интерфейс создания и управления целью
- Карточки целей с прогресс-барами
- Интеграция целей в дашборд
- Финальная полировка UX

**Задачи QA**:
- End-to-end тестирование пользовательских сценариев
- Тестирование на разных браузерах и устройствах  
- Нагрузочное тестирование API

**Критерии готовности**:
- Все пользовательские истории проходят приёмочные тесты
- Приложение стабильно работает при 50+ одновременных пользователях
- Время отклика основных операций < 1 сек

## Тестирование

### Автоматизированное тестирование
- **Unit тесты**: Backend сервисы (Jest)
- **Integration тесты**: API endpoints (Supertest)  
- **Component тесты**: React компоненты (React Testing Library)
- **E2E тесты**: Критичные пути пользователей (Playwright)

### Ручное тестирование
- **Smoke тесты**: Основные функции работают после каждого релиза
- **Usability тесты**: 3-5 пользователей тестируют интерфейс  
- **Cross-browser тесты**: Chrome, Firefox, Safari, Edge
- **Mobile тесты**: iOS Safari, Android Chrome

### Критерии качества  
- Unit test coverage > 80%
- E2E тесты покрывают 100% критичных путей
- Все найденные баги приоритета High/Critical исправлены
- Performance: загрузка страниц < 3 сек, API < 1 сек

## Риски и митигация

### Высокие риски
- **Производительность календаря**: Много операций + расчёты остатков
  - *Митигация*: Кэширование, оптимизированные SQL запросы, пагинация
- **UX кассового календаря**: Пользователи могут не понять концепцию  
  - *Митигация*: Дополнительные подсказки, онбординг, A/B тесты интерфейса

### Средние риски
- **Сложность расчёта целей**: Алгоритмы могут дать неожиданные результаты
  - *Митигация*: Обширные unit тесты, валидация с финансовыми экспертами
- **Задержки в разработке**: Новая команда, сложность задач
  - *Митигация*: Ежедневные стендапы, еженедельные ретро, буферное время
