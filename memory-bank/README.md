# FinFocus Memory Bank

**Memory Bank** - система документации проекта для AI агентов, оптимизированная для быстрого понимания и поддержки.

## Что это?

Memory Bank обеспечивает:
- **Быстрое погружение** - 3-5 минут для понимания проекта
- **Актуальность** - регулярные обновления с кодом
- **Краткость** - 20-30 строк для каждого модуля
- **Полнота** - достаточно для работы без чтения всего кода

## Структура документации

### Главное (КРИТИЧНО)
Прочитать в первую очередь:

1. **[index.md](index.md)** - главное оглавление, с чего начать
2. **[architecture.md](architecture.md)** - архитектура системы, слои, паттерны
3. **[tech-stack.md](tech-stack.md)** - технологии, версии, зависимости
4. **[code-style.md](code-style.md)** - стандарты кода, git workflow, batch process

### Модули системы (краткие)
Описания 20-30 строк для каждого модуля:

- **[modules/database.md](modules/database.md)** - SQLAlchemy ORM модели
- **[modules/services.md](modules/services.md)** - бизнес-логика, валидация
- **[modules/ui-components.md](modules/ui-components.md)** - Dash UI компоненты
- **[modules/routing.md](modules/routing.md)** - URL-based routing

### Процессы (по необходимости)
- **[testing.md](testing.md)** - стратегия тестирования, fixtures
- **[deployment.md](deployment.md)** - запуск, деплоймент, environment variables

## Быстрый старт для AI

**При старте новой сессии (3-5 минут)**:
1. Прочитать `@memory-bank/index.md` - понять суть проекта
2. Прочитать `@ROADMAP.md` - актуальные приоритеты
3. Прочитать `@.reports/notes/feature_progress.md` - последние изменения

**При работе над задачей**:
1. Определить тип задачи → прочитать соответствующий `modules/*.md`
2. Если новый паттерн → проверить `code-style.md`
3. Если изменение архитектуры → проверить `architecture.md`

## Принципы Memory Bank

### 1. Минимализм
- Краткие файлы (20-30 строк для модулей)
- Только важная информация
- Ссылки на детали вместо копирования

### 2. Актуальность
- Обновление вместе с кодом
- Удаление устаревшей информации
- Версионирование через git

### 3. Для AI, не для людей
- Структурированный формат
- Конкретные примеры кода
- Ссылки на файлы с номерами строк

### 4. Проверяемость
- Все утверждения проверяемы в коде
- Указание путей к файлам
- Примеры с реальным кодом

## Что НЕ документируем

❌ **Очевидные вещи** (Dash - это Python фреймворк)
❌ **Дубли кода** (копирование целых файлов)
❌ **Изменчивые данные** (список всех 142 операций)
❌ **Временные решения** (TODO комментарии)

## Когда обновлять

**ОБЯЗАТЕЛЬНО**:
- После изменения архитектуры → `architecture.md`
- После добавления технологии → `tech-stack.md`
- После изменения стандартов → `code-style.md`
- После создания модуля → `modules/*.md`

**РЕКОМЕНДУЕТСЯ**:
- После каждого батча → `index.md` (прогресс)
- После багфикса → соответствующий модуль
- После рефакторинга → `architecture.md` (паттерны)

**НЕ НУЖНО**:
- После мелких изменений в коде
- После изменения UI текстов
- После обновления зависимостей (minor versions)
