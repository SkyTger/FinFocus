# 0030 — Карточки-двери щитка (Epic-11, кусок 2 из 3)

## ADR-style Summary

- **Context**: Epic-11 «щиток», кусок 1 (модель «свободно/платежи/резерв» + шапка + график полос) смержен протоколами 0028/0029, 693 теста зелёные. Кусок 2 по концепции design.md делает дашборд единственной навигацией: карточки-двери вместо меню. Решение спроектировано циклом `/design-loop` — 4 итерации, финал `solution-v4.md` (⭐4/5, блокеров нет), покрытие спеки 25/25 (PASS).
- **Problem Statement**: Дашборд не отвечает на вопрос «куда идти» и дублирует цифры разными способами (P1-боль UX-аудита 2026-08-20). Разделы находимы только через сайдбар; карточки старой раскладки (readonly-подушка, split-таблицы операций) считают своё своим способом и могут разойтись с шапкой.
- **Decision**: Один сбор данных щитка новым read-only композитором `DashboardPanelService` за **одну** сессию БД (было 3 на пути сборки) → `PanelData` с пятью срезами карточек. Карточки-двери — обычные `dcc.Link` (ни одного нового серверного Input, класс регрессий C-6 не создаётся конструктивно). Сайдбар снимается с дашборда и переводится на один колбэк `render_sidebar_slot(pathname, profile_updated)` с чтением профиля при построении — оба прежних колбэка сайдбара удаляются, условно присутствующих Output'ов не остаётся. Переходы с контекстом — расширение существующего механизма query params с явным контрактом владения `url.search` по pathname.
- **Alternatives**: (1) Сдвиг окна модели слоёв назад ради «вчера» — **отброшен владельцем** (менял основу, на которую опирается кусок 1; критик нашёл три недоучтённых места). (2) Отдельное поле `yesterday` в модели — спроектировано в v2-v4, но **снято решением владельца 2026-08-26**: расчёт «вчера» три итерации подряд порождал тихие дефекты. (3) Guard'ы вместо удаления колбэков сайдбара — отброшены: маскируют гонку, а не снимают её. (4) Кеш данных карточек — отброшен: единственный источник инвалидации уже перерисовывает щиток, кеш дал бы риск устаревших цифр.
- **Consequences**: Дашборд теряет сайдбар (промежуточное состояние до куска 3 — полоски-меню). `MoneyLayersService` куском 2 **не затрагивается вообще** (решение владельца про «вчера»): контракт `MoneyLayersData` не меняется, C-5 не используется, 47 тестов визуального слоя щитка не правятся. Карточка «Календарь» показывает **сегодня и завтра** — сужение FR-1.a спеки, зафиксировано осознанно. Три урока идут в knowledge-bank: два вопроса к оконному хелперу, проверка `__init__` перед передачей сессии, перечень сессий строится командой.

## Generic Principles

См. `~/.claude/templates/protocol/principles.md.tpl`

**Дополнительно для этого протокола:**

1. **Прежде чем утверждать поведение приватного хелпера — открыть его тело**, а не подпись и не докстринг. Цикл проектирования трижды спотыкался именно на этом.
2. **Перед передачей сессии в конструктор сервиса — проверить, что `__init__` у него есть.** `AllocationService` — единственный сервис проекта без него; `AllocationService(session)` даёт `TypeError`, который блочный `except` превращает в молчаливую деградацию карточки.
3. **Перечень сессий БД строится командой**, а не памятью: `grep -rn get_db_session app/components/ app/main.py` + разбор каждого попадания по признаку «срабатывает ли колбэк на этом пути». Трижды подряд перечень был неполон.
4. **Класс регрессий C-6 работает в обе стороны**: добавляешь элемент, живущий не на всех страницах — только через Store-триггер; **удаляешь элемент — удаляй и его Input**.
5. **Тест инварианта суммы слоёв не ловит дефекты слагаемых.** Если проверяется значение — ассерт на само значение плюс порча кода, иначе тест бесполезен.
