# Шаг 5: Документы решений и скрипт живой приёмки

## Briefing

- **Цель:** Отменённые решения помечены там, где их найдут; справочник
  по коду актуален; есть скрипт, которым основная сессия проверит
  результат на копии боевой базы.
- **Ключевые файлы:** `.obsidian-docs/design/epic-11-panel-batch-1/spec.md`,
  `.obsidian-docs/adr/` (новый ADR-006), `.obsidian-docs/knowledge-bank/modules/services.md`,
  `modules/ui-components.md`, `modules/schema.md`, `knowledge-bank/protocols.md`,
  `scripts/` (новый скрипт приёмки)

## Sub-tasks

1. Спека Epic-11 кусок 1: у C-5, FR-3.e, AC-1, п.3а — пометка
   «⚠️ Пересмотрено протоколом 0033 (2026-11-03): …» с одной строкой
   нового смысла. Текст решений не удалять.
2. ADR-006 «Можно тратить: суффиксный минимум доступного и лимит по
   периодам» — контекст, решение (формулы), отменённые решения,
   блок **КРИТИЧНО**: `_split_day` единственный механизм сжатия;
   резерв берётся того же дня t; дни включительно.
3. knowledge-bank: MoneyLayersService (новые поля, горизонт H, удалённые
   поля), щиток (шапка, маркер), schema; запись 0033 в protocols.md.
4. Скрипт `scripts/acceptance_safe_to_spend.py`: принимает путь к базе
   аргументом, открывает ТОЛЬКО на чтение (`sqlite:///file:...?mode=ro&uri=true`
   или копия во временный файл), печатает на ref (аргумент, по
   умолчанию сегодня): free сегодня, периоды лимита, узкое место,
   норму, нехватку, прогноз остатка на конец каждого периода. Запуск
   по боевой базе в протоколе НЕ делать — это работа основной сессии
   при приёмке.
5. Коммит.

1. Sub-tasks последовательно
