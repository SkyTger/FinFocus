# Шаг 2: Лимит по периодам и норма

## Briefing

- **Цель:** Модель отдаёт `limit_periods`, узкое место (конец первого
  периода), `norm_per_day`. Алгоритм — plan.md, «Лимит по периодам».
- **Ключевые файлы:** `app/services/money_layers_service.py`,
  `tests/test_money_layers_service.py` (или новый
  `tests/test_money_layers_limit.py`, если так чище)
- **Доп. информация:** Деление Decimal — `per_day` хранить Decimal,
  округление до рубля ВНИЗ (ROUND_DOWN) только при сравнении для
  слияния и в UI. Дни включительно с обоих концов.

## Sub-tasks

1. Периоды: жадный алгоритм из plan.md (при равенстве — ПОСЛЕДНИЙ
   t), до 3 периодов, слияние равных, `reliable`, `L < 0 → per_day 0`.
2. Узкое место = конец первого периода; `bottleneck_available` =
   `available` в этот день. Заменить временное значение шага 1.
3. Норма: регулярные вхождения в календарный месяц ref (доходы −
   расходы) ÷ дней месяца; нет регулярных → None.
4. Тесты (ожидания — ручной расчёт в log.md):
   - **ноябрьский сценарий** (синтетический, даты относительно ref
     через хелперы conftest): остаток на ref, доход 100 000 через
     2 дня (аналог 5-го) и через 17 (аналог 20-го), регулярные платежи
     по таблице `.obsidian-docs/budget/state.md` недоступна в worktree —
     взять из `.obsidian-docs/ROADMAP.md` п.10/решения консилиума или
     составить правдоподобный набор; разовые 23 500 до второго дохода и
     20 000 после. Проверить: два периода, первый кончается накануне
     второго дохода, `per_day` второго ≥ первого;
   - перенос «радиатора» до второго дохода → нехватка > 0, лимит 0;
   - **контрпример**: available 10 000 на день 16 и 15 000 на день 37
     (иначе выше) → лимит 405 (15 000 // 37), не 625;
   - **октябрьский сценарий**: регулярный доход по плану 100 000, а на
     ref уже внесена фактическая операция меньше — норма считается по
     плану (шаблон), подпись — забота UI; тест фиксирует, что норма
     НЕ подстраивается под факт (осознанное поведение, риск в решении);
   - слияние: периоды с равным лимитом → один;
   - нет доходов в горизонте → период ненадёжен.
5. black / flake8 / pytest.
