### Step 02 — Лимит по периодам и норма

**Сделано:**

  сравнение отношений перекрёстным умножением (без деления), при

- `_merge_equal_periods`: соседние с равным лимитом до рубля вниз

  первый период растворился бы в ненадёжном и UI показал бы
  предупреждение вместо известного числа) — уточнение плана, в плане
  этот случай не описан.
- Узкое место = конец первого периода, `bottleneck_available` =
  `available` этого дня (временное значение шага 1 заменено).
- `_norm_per_day`: по ШАБЛОНАМ (виртуальные вхождения
  `generate_instances` в календарный месяц ref, исключения не
  учитываются — «по плану»); доход +, типы слоя «Платежи» (expense и
  savings) −; ÷ дней месяца; нет вхождений → None. Шаблоны берутся из
  уже существующего запроса `_user_data_markers` (он теперь отдаёт
  список, а не bool) — лишнего запроса нет.

  оси: window_end = M/3 + 44 ∈ [M+1/16, M+1/19] при любой длине M).
