# 0034-one-off-expenses — Разовые траты отдельно от регулярных

## ADR-style Summary

- **Context**: Владелец ведёт в FinFocus настоящий бюджет (режим co-pilot).
  Регулярные платежи для него — фон, а дыры в бюджете делают крупные
  разовые траты (ремонт машины, свадьба, подарки) — это решения, которые
  можно двигать. Сейчас разовое и регулярное на щитке неразличимы.
  Решение владельца 2026-11-03 — ROADMAP п.10 P2 «Разовые траты отдельно
  от регулярных», пункты 1–3 приняты, п.4 отложен.
- **Problem Statement**: Слой «Платежи» на графике полос — один цвет для
  всего. В календаре точка «расход» общая для разовых и регулярных, в
  списке операций у регулярных есть значок повтора, а разовые ничем не
  отмечены. Ответить взглядом на «что за горб и когда» нельзя.
- **Decision**: Показ, а не новая модель. (1) Засечки разовых расходов
  на графике щитка — маркер над столбцом дня, подробности в подсказке
  при наведении, подписи у самых крупных; (3) строка в шапке «Разовые
  траты до <узкое место>: N ₽»; (2) отличимая отметка разовых расходов
  в календаре и в списке операций. Один признак «разовый расход» и один
  цвет — везде.
- **Alternatives**: Разрезать полосу «Платежи» на два цвета (п.4) —
  ОТВЕРГНУТО в этом протоколе: после протокола 0033 полоса — остаток за
  вычетом будущих доходов, деление требует произвольного правила «кого
  покрыл аванс» (ADR-006). Порог «крупной» траты настройкой — отвергнуто
  (владелец против новых «крутилок»).
- **Consequences**: Формулы модели слоёв НЕ меняются (ADR-006, все
  существующие тесты модели слоёв проходят без правки ожиданий). Одно
  новое поле у предстоящего платежа, одна чистая функция группировки,
  один новый цветовой токен. Миграций БД нет, настроек нет, новых
  сущностей нет.

## Спецификация (контракт)

**Разовый расход** — операция с `transaction_type == "expense"`, которая
НЕ принадлежит серии: не шаблон, не виртуальный экземпляр, не исключение
серии. В данных календаря (`TransactionInfo`) это
`is_recurring is False and is_virtual is False` (у исключений
`is_recurring=True`, см. `calendar_service.py:560-572, :861-909`).
В ORM — `tx.is_recurring is False and tx.recurring_parent_id is None`.
Служебные операции (savings_reserve, savings_contribution, adjustment) —
НЕ разовые, даже если не в серии. Признак не зависит от суммы и даты.

**Модель** (`app/services/money_layers_service.py`, `app/schema/money_layers.py`):
- `UpcomingPayment` получает поле `is_one_off: bool` по правилу выше,
  заполняется в `_collect_operations` (там уже есть `transaction_type` и
  `is_recurring`; `is_virtual` взять из того же `txn`). Остальные поля и
  состав списка платежей — без изменений.
- Новая чистая функция рядом с `bottleneck_marker` (тот же паттерн —
  единый источник для графика и шапки):
  `one_off_marks(data) -> list[OneOffMark]` — разовые расходы из
  `data["upcoming_payments"]` с датой в [reference_date, window_end],
  сгруппированные по дню, по возрастанию даты. `OneOffMark` (TypedDict в
  schema): `date`, `total: Decimal`, `items: list[UpcomingPayment]`
  (в порядке убывания суммы).
- `one_off_total_until(data, end: date) -> Decimal` — сумма разовых
  расходов с датой в [reference_date, end] (по `upcoming_payments`, т.е.
  может выходить за ось, до H). Тоже чистая функция.
- Ни `_split_day`, ни слои, ни лимит, ни горизонт не трогать.

**График** (`build_layers_chart`, `app/components/dashboard.py`):
- Один `go.Scatter` «Разовые траты»: по точке на каждый `OneOffMark`,
  x = дата, y = верх столбца дня (`max(forecast_balance, 0)` этого дня
  из `data["days"]`), маркер `triangle-down` цвета `ONE_OFF_COLOR`,
  размер ~10. Подсказка (hovertemplate/hovertext) — список трат дня:
  «<описание или категория или «Расход»> — <format_rub>», каждая с новой
  строки; при `hovermode="x unified"` она встаёт в общую подсказку дня.
- Подписи текстом — только у трёх крупнейших дней по `total` (константа
  `ONE_OFF_LABELS_MAX = 3`, не настройка): «<описание самой крупной
  траты, обрезано до 16 симв. с «…»> <сумма дня>», если трат в дне
  несколько — «<N> траты · <сумма>». Подписи над маркером, не у оси X
  (там вехи целей) и не мешают маркеру узкого места.
- Нет разовых в окне — следа нет вовсе (никаких пустых трасс с легендой).
- Полоса «Платежи» остаётся одноцветной.

**Шапка** (`_build_limit_block`):
- Новая строка «Разовые траты до <format_date_human(bottleneck_date)>:
  <format_rub(сумма)>» — сумма = `one_off_total_until(data,
  bottleneck_date)`. Показывать, только если `bottleneck_date` не None и
  сумма > 0. Стоит после строк лимита (и после строки нехватки, если
  она есть), класс `pnl-limit-sub`. Маленький маркер-кружок цвета
  разовых перед текстом — связь с засечками графика.
- Подсказка `LIMIT_HINT` дополняется одной фразой: что такое разовые
  траты и что они отмечены на графике треугольниками.

**Календарь** (`app/components/calendar.py`, `app/assets/calendar.css`):
- Точки дня: разовый расход даёт отдельную точку `txn-dot one-off`
  (title «Разовый расход») цвета токена разовых; точка `expense`
  (title «Расход») остаётся только для расходов серий. Точки дохода и
  «Повторяющаяся» — без изменений.
- В подсказке дня (строка операции) разовый расход помечен тем же
  цветом (маленький кружок или цветная полоска у строки — на выбор
  исполнителя, но один приём).

**Список операций** (`app/components/transactions.py`, ~:570-585):
- У строки разового расхода — значок на месте значка повтора: иконка
  `bi-flag-fill` (проверено: есть в bootstrap-icons@1.10.3, которую
  подключает dbc; урок протокола 0031 — `bi-target` не существовал),
  цвет разовых, `title="Разовая трата"`.

**Цвет**: один токен `--color-one-off: #8e44ad` в `:root` в
`app/assets/custom.css` (рядом с `--color-expense`), в Python — константа
`ONE_OFF_COLOR = "#8e44ad"` рядом с `LAYER_COLORS`. Якорный тест: значения
совпадают (CSS ↔ Python). Цвет не пересекается с токенами слоёв
(#2ecc71/#f0b775/#3498db) и расход/доход (#f43f5e/#2ecc71); контраст с
белым ≥ 3:1.
