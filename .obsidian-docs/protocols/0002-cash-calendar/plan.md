# 0002 — Кассовый календарь с расчетом остатков

## ADR-style Summary:

- **Context**: FinFocus — приложение для планирования личного бюджета. Фаза 3 Epic-01-CoreMVP требует реализации кассового календаря — главной фичи MVP, позволяющей пользователю видеть прогноз остатков средств на каждый день месяца.

- **Problem Statement**: Пользователю необходим визуальный инструмент для понимания своего финансового положения на каждый день. Текущая реализация содержит только страницу транзакций без агрегации и прогнозирования.

- **Decision**: Реализовать кассовый календарь с тремя компонентами:
  1. **CalendarService** — сервис расчета остатков с SQL агрегацией
  2. **calendar.py** — UI компонент календарной сетки
  3. **Dash callbacks** — интерактивность с guard clauses по ADR-003

- **Alternatives**:
  1. Использовать готовую библиотеку календаря (dash-mantine-components) — отклонено из-за сложности кастомизации и лишних зависимостей
  2. Рассчитывать балансы на клиенте через JavaScript — отклонено из-за производительности и дублирования логики

- **Consequences**:
  - (+) Единая логика расчета в backend
  - (+) SQL агрегация — высокая производительность
  - (+) Переиспользование существующего create-modal из transactions.py
  - (-) Необходимость сериализации Decimal для dcc.Store
  - (-) Дополнительные guard clauses для Pattern-Matching callbacks

## Generic Principles (MUST follow):

1. **Баланс и простота**: Избегаем оверинжиниринга. Решения — самые простые из возможных, но функциональные и надежные.

2. **Никакого легаси**: Удаляем устаревший код. Обратная совместимость не требуется.

3. **Стандарты кодирования**:
   - Python 3.12+ с type annotations
   - Docstrings на русском языке
   - Black (88 chars) + flake8 для форматирования
   - Guard clauses pattern для callbacks

4. **Качественные тесты**: Покрытие pytest для критической логики CalendarService.

5. **Детализация**: План самодостаточен для выполнения без дополнительного контекста.

6. **Pattern-Matching Callbacks** (КРИТИЧНО, ADR-003):
   ```python
   # Guard #1: проверка triggered_id
   if not triggered_id:
       raise PreventUpdate

   # Guard #2: проверка типа (для Pattern-Matching)
   if not isinstance(triggered_id, dict) or triggered_id.get("type") != "expected-type":
       raise PreventUpdate

   # Guard #3: проверка реального клика
   if not ctx.triggered or ctx.triggered[0].get("value") is None:
       raise PreventUpdate
   ```

7. **Decimal сериализация**: Использовать `str()` для JSON-совместимости в dcc.Store.

8. **TRANSFER транзакции**: Исключаются из расчетов баланса (внутренние переводы).
