# 0006 — Множественные накопительные цели с приоритетами

## ADR-style Summary:

- **Context**: Текущая реализация FinFocus ограничивает пользователя одной активной накопительной целью (ограничение D009 в GoalService). Это значительно снижает ценность приложения, т.к. реальные пользователи обычно копят на несколько целей одновременно (отпуск, автомобиль, подушка безопасности).

- **Problem Statement**: Как разрешить пользователям создавать множество активных целей с автоматическим распределением бюджета накоплений между ними по приоритетам?

- **Decision**: Реализовать систему множественных целей с приоритетами (1 = самый важный) и жадным алгоритмом распределения бюджета. Приоритет 1 получает финансирование первым, остаток распределяется на следующие. UI использует кнопки вверх/вниз для изменения приоритетов (drag-and-drop отложен).

- **Alternatives**:
  1. Равное распределение бюджета — отвергнуто (не учитывает срочность целей)
  2. Процентное распределение — отвергнуто (сложнее для пользователя)
  3. Drag-and-drop для приоритетов — отложено (требует verification spike для dash-draggable)

- **Consequences**:
  - (+) Пользователь может копить на множество целей одновременно
  - (+) Автоматический расчет рекомендуемых взносов
  - (+) Предупреждения о недостаточном бюджете
  - (-) Требуется миграция БД (новое поле monthly_savings_budget)
  - (-) UI становится сложнее (список карточек вместо одной)

## Generic Principles (MUST follow):

1. **Баланс и простота**: Избегай оверинжиниринга. Решения — самые простые из возможных, но функциональные. Не добавляй абстракции "на будущее".

2. **Никакого легаси**: Удаляй устаревший код (D009 ограничение). Обратная совместимость не требуется.

3. **Стандарты кодирования**:
   - Python 3.12 с type annotations
   - Docstrings на русском языке
   - Black (88 chars) + flake8
   - Guard clauses в начале функций

4. **Session Management**: Сервисы используют `flush()`, caller делает `commit()`.

5. **Pattern-Matching Callbacks**: Проверять `ctx.triggered[0].get('value') is None` для фильтрации автовызовов (ADR-003).

6. **Качественные тесты**:
   - Минимум 16 тестов (7 AllocationService + 6 GoalService + 3 интеграционных)
   - Использовать существующие fixtures из conftest.py
   - Каждый тест проверяет ОДНУ конкретную вещь

7. **Документация**: После завершения обновить ROADMAP.md и feature_progress.md.
