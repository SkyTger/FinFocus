# Шаг 1: Проверка гипотезы реконсиляции

## Briefing

- **Цель:** Эмпирически проверить, переиспользует ли React DOM-узел слота при переходе раздел→раздел. На этом стоит весь FR-2/AC-5. Проверка идёт **ДО единого удаления** — если гипотеза не подтвердится, откатывать нечего.
- **Ключевые файлы:**
  - `app/assets/sidebar.css` — сюда временно добавляется проба
  - `app/components/sidebar.py:178-180` — `create_sidebar` возвращает `dbc.Card(className="sidebar-card")` **без `id`**
  - `app/main.py:129-179` — `render_sidebar_slot`, тот же слот-колбэк, что будет у полоски
- **Доп. информация:** Запуск ТОЛЬКО из `.venv` (dash 2.17.1; системный python несёт 3.2.0). Обе правки временные, в коммит НЕ попадают.

## Почему двух проб мало одной

У живого `.sidebar-card` нет `id`, а целевая конструкция — `.nav-rail` **с** `id`. Это два разных режима реконсиляции: без `id` React-ключ обёртки `undefined` → сопоставление по индексу; с `id` → именованный ключ (`createContainer` ~3972 в `dash_renderer.dev.js`: `key: stringifyId(component.props.id) || key`; `getChildren` ~4035 четвёртый аргумент не передаёт). Проба только в первом режиме на второй не переносится.

## Sub-tasks

1. **Проба 1.a — контроль (индексное сопоставление).**
   Временно в `app/assets/sidebar.css`:
   ```css
   @keyframes __probe { from {opacity:.3} to {opacity:1} }
   .sidebar-card { animation: __probe 1s; }
   ```
   Запустить `python run.py` из `.venv`, пройти `/calendar → /goals → /analytics`.

2. **Проба 1.b — целевой режим (именованный ключ).**
   Дополнительно временно добавить `id="__probe-rail"` в `dbc.Card` внутри `create_sidebar`. Те же переходы.

3. **В обеих пробах наблюдать:**
   - (а) моргает ли карточка на каждом переходе;
   - (б) срабатывает ли `animationstart` (DevTools → Sources → Event Listener Breakpoints → Animation, либо разовый слушатель из консоли);
   - (в) **прямое наблюдение идентичности**, не опосредованное анимацией: выделить узел в Elements, запомнить как `$0`, перейти в другой раздел, проверить `document.contains($0)` → `true`.

4. **Записать результат обеих проб в `log.md` дословно** — это единственная эмпирика под FR-2, и через протокол она достанется следующему куску.

5. **Откатить обе временные правки** (`git checkout app/assets/sidebar.css app/components/sidebar.py`), убедиться `git status` чист.

## Матрица исходов — действие по каждому

| 1.a (без `id`) | 1.b (с `id`) | Вывод и действие |
|---|---|---|
| не моргает | не моргает | Гипотеза подтверждена в обоих режимах → идти дальше по основному пути; `id` остаётся страховкой от вставки второго элемента в слот (Epic-08) |
| моргает | не моргает | Индексное сопоставление ненадёжно, **именованный ключ и есть решение** — выбор решения усилен эмпирикой → идти дальше |
| — | моргает | Механизм не работает и штатным средством не чинится → **план Б2: вынос FR-2/AC-5 в Epic-10**, кусок закрывается по остальным десяти AC. **Решение принимает владелец** — остановиться и спросить |

Четвёртый исход («1.a не моргает, 1.b моргает») физически невозможен: `id` в решении константа, а совпадающий именованный ключ — более сильная гарантия сопоставления, чем позиционная.

## Чего шаг 1 НЕ проверяет

Проба идёт на `opacity`, целевая анимация — `clip-path`. Для вопроса «монтируется или патчится» разницы нет, но вопрос «сыграет ли `clip-path` как задумано и не останется ли остаточного отсечения» закрывается только на шаге 8.
