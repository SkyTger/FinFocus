# 0031-nav-rail — Полоска-меню вместо сайдбара (Epic-11, кусок 3)

## ADR-style Summary

- **Context**: Последний кусок редизайна «щиток». Куски 1 (0028, модель слоёв + шапка + график) и 2 (0030, карточки-двери + снятие сайдбара с дашборда) смержены. Сейчас на не-дашборд экранах стоит широкий сайдбар 288px — стеклянная карточка с профилем сверху, пятью подписанными пунктами, «Настройками» и зашитой версией «v1.0.0» внизу.
- **Problem Statement**: Сайдбар отъедает 288px у содержимого на всех экранах, кроме дашборда; ведёт на несуществующий `/settings` (P1 UX-аудита 2026-08-20); показывает версию, разошедшуюся с реальной (P3 того же аудита). Дашборд после куска 2 — единственная полноценная навигация, а сайдбар дублирует её в устаревшей форме.
- **Decision**: Заменить сайдбар узкой полоской иконок 60px (`app/components/nav_rail.py` + `nav_rail.css`): знак-домик наверху ведёт на дашборд, четыре раздела иконками, аватар внизу открывает профиль, подписи — язычком при наведении, активный раздел подсвечен пилюлей. Разворот при входе с дашборда — CSS-анимация на монтировании узла; носитель идентичности узла — `id="nav-rail"` (React-ключ обёртки = `stringifyId(props.id)` в dash-renderer 2.17.1). Версия переезжает в окно профиля из нового `app/version.py`.
- **Alternatives**: (A) выбрана — `@keyframes` на монтировании + `id` как носитель тождества. (B) CSS-`transition` — отвергнут: на монтировании физически не играет, нет стартового значения. (C) clientside-колбэк с хранением предыдущего pathname — **отвергнут владельцем окончательно**: Output на условно присутствующий элемент = гонка со слот-колбэком, класс регрессий, дважды чиненный проектом (0026, 0028). (D) проп `key=` — отвергнут фактически: в Dash 2.17 на реконсиляцию обёртки не влияет, а `dcc.Link` его не принимает (`TypeError`).
- **Consequences**: Содержимому возвращается 228px на четырёх экранах. Закрываются P1 и P3 UX-аудита. Имя пользователя уходит из навигации (в 60px не влезает) — компенсируется окном профиля. Появляется единственный источник версии, устойчивый к PyInstaller-бандлу. Разворот принимает отступление от раскадровки эскиза (плашка не растёт, содержимое проявляется) — решение владельца ради сохранности язычков.

## Наследуемые инварианты (протокол 0030) — ломать нельзя

1. **У компонента меню НЕТ ни одного серверного обработчика.** Подсветка и профиль вычисляются на построении чистой функцией. Регрессионный якорь — тест в `tests/test_nav_rail.py`.
2. **Колонку схлопывает РОВНО ОДНО правило CSS `:empty`.** Второй механизм скрытия (переключение класса обработчиком) не вводить — это был бы второй источник правды о видимости.
3. **Вход в окно профиля — только через Store-триггер.** Прямая привязка обработчика к условно присутствующему элементу молча отключает колбэк целиком; проект ловил этот класс регрессий дважды (0026, 0028).
4. **Владение адресной строкой не меняется.** `/transactions` принадлежит фильтру периода (0023), `_OWNED_SEARCH_PATHS` остаётся `{"/calendar", "/goals"}`; переходы с контекстом куска 2 продолжают работать.

Дополнительно: **`id="nav-rail"` на кожухе — носитель React-идентичности, а НЕ точка привязки колбэка.** Output на него был бы гонкой со слот-колбэком, создающим тот же узел.
