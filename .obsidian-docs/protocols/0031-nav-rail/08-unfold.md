## Sub-tasks

1. `@keyframes nav-rail-unfold` на **`.nav-rail-inner`** (не на кожух):
   ```css
   @keyframes nav-rail-unfold {
     /* Видимая зона кадра 0 = padding-top (10) + логотип (44) = 54px.
        Выражением от тех же переменных, что и остальная геометрия. */
     from { clip-path: inset(0 0 calc(100% - (10px + var(--rail-slot))) 0); opacity: .35; }
     to   { clip-path: inset(0 0 0 0);                                      opacity: 1;   }
   }
   .nav-rail-inner { animation: nav-rail-unfold 220ms cubic-bezier(.2,.8,.2,1) backwards; }
   ```
   **`backwards`, а НЕ `both`**: `both` оставил бы `to`-кадр (`clip-path: inset(0)`) на узле навсегда, а `inset(0)` обрезает по border-box и срезал бы язычок. При нулевой задержке `backwards` собственного эффекта не имеет — он взят ровно ради отсутствия остаточного состояния.

2. `@media (prefers-reduced-motion: reduce) { .nav-rail-inner { animation: none } }` — обнуляется `animation` **целиком**, не только `duration`, иначе `from`-кадр применится и залипнет.

3. **Живая проверка AC-5, оба сценария:**
   - (а) `/dashboard` → дверь «Календарь» → разворот сверху вниз;
   - (б) `/calendar` → слот «Цели» → разворот **НЕ повторяется** (`animationstart` не срабатывает; узел `.nav-rail` в Elements не подсвечивается как пересозданный);
   - дополнительно: `/goals` → логотип → `/dashboard` → слот раздела → разворот играет снова.

4. **Проверка остаточного отсечения:** после завершения разворота в DevTools → Computed на `.nav-rail` и `.nav-rail-inner` **нет `clip-path`**; то же при включённом `prefers-reduced-motion: reduce`. Навести на слот в обоих режимах — язычок виден целиком.

5. AC-6 живьём: DevTools → Rendering → Emulate CSS `prefers-reduced-motion: reduce` → полоска сразу целиком, без анимации, ничего не залипло на `from`-кадре.

## Отступление от раскадровки — принято, не обсуждается заново

В эскизе (`v4.html`, блок 3) схлопывается **сама стеклянная плашка** (`.frame-rail.cut{height:118px}` на `.rail` — узле с фоном, границей, тенью и `overflow: hidden`). Решение анимирует только содержимое внутри неподвижной плашки. **Решение владельца Р5 (2026-08-28): подписи важнее буквального роста плашки** — рост требует обрезки по краю кожуха и срезал бы язычки постоянно. Отступление зафиксировано письменно (RTM #72), прецедент — кусок 2 (окошко «вчера»). Возвращать `clip-path`/`max-height` на кожух не нужно: это не воспроизводит кадр эскиза и возвращает снятый дефект.
