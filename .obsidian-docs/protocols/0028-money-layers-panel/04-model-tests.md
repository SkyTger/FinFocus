# Шаг 4: Тесты модели — таблица ожидаемых слоёв и 9 других блоков

## Briefing

- **Цель:** Покрыть модель тестами так, чтобы неверная раскладка слоёв падала. Инвариант суммы (AC-3) этого не даёт — он зелёный при любой раскладке, и именно поэтому два блокера дожили до третьей итерации проектирования.
- **Ключевые файлы:**
  - `tests/test_money_layers_service.py` — НОВЫЙ
  - `tests/conftest.py` — переиспользовать хелперы относительных дат (**не** захардкоживать даты, KB `testing.md`)
- **Источник правды:** solution-v4.md, шаг 6 плана — состав 10 блоков; «Численная трассировка» — числа для кейсов 1–12b.
- **Соответствует шагу 6 плана решения** (оценка 9.5 ч — самый дорогой шаг, и не случайно).

## Sub-tasks

**Блок A — «таблица ожидаемых слоёв» (главный, обязательный).**
`@pytest.mark.parametrize` с явными **числами по всем трём слоям** (`free`, `payments`, `reserve`), не только по сумме. Матрица: режим (`fixed_date` / `from_balance`) × доля взноса (0 / частичный / полный бюджет) × позиция дня (до даты резерва / день резерва / после / последний день месяца / первый день следующего / после резерва следующего месяца / правый край окна).

Обязательно включить кейсы из трассировки решения:
- **кейс 2**: `fixed_date` + взнос 5 000 из 15 000 → `goals_part == 5 000` (v2 давал 0 — этот тест ловит блокер №1)
- **кейс 8**: `from_balance` + взнос 5 000 с будущей датой → `goals_part == 10 000` (v2 давал 5 000)
- **кейс 9**: границы месяцев → 31 авг / 26 сент / 30 сент == 0 (v2 давал 15 000 / 30 000 / 30 000 — этот тест ловит блокер №2)
- **кейс 10**: бюджет уменьшен после частичного взноса → `goals_part == 0`, `reserve_configured == 30 000`, **+ ассерт отсутствия признака перерасхода в контракте** (решение владельца «промолчать» защищено тестом, а не подразумевается)
- **кейс 11**: бюджет увеличен после полного взноса → `goals_part == 12 000`, `reserve_configured == 42 000`

**Блок B — инвариант AC-3** параметризованно по всем 45 дням: `free + payments + reserve == forecast_balance` и `forecast_balance == calculate_daily_balances()[date]`. Кейсы: положительный / нулевой / отрицательный остаток, дефицитный каскад, оба режима, дни по обе стороны границы месяца.

**Блок C — «таяние» платежей:** монотонно не растёт; `payments(payments_end) == 0`; `payments(D) == 0` за границей месяца; `payments(D)` не включает платежи дня D.

**Блок D — каскад `_split_day`:** три ветки с assert суммы; сжатая полоса (`reserve < reserve_configured`, `reserve == balance` при `payments == 0`).

**Блок E — порог подушки:** `cushion_part` не сжимается вне каскада; перенакопленная подушка (накоплено 922 155 при пороге 30 000) → `reserve_configured == 30 000`; используется порог, а не `target`.

**Блок F — границы:** последний день месяца, 1-е число, февраль, 31-е, переход через год, окно через три месяца (25 дек), **+ новый тест «exception перенесён в другой месяц»** (кейс 12): `original_date = 25 сент`, `transaction_date = 8 окт` → числа по трём слоям для D = 30 сент (`goals_part == 15 000`) и D = 5 окт (`goals_part == 0`), + assert наличия ключа за `window_end` в `savings_by_date`.

**Блок G — пустые состояния:** `is_empty` (чистая база; онбординг пропущен через `skip()`) vs `window_is_flat` (история есть, окно пустое → график рисуется) + **assert «в `_is_empty` нет обращений к БД»** (счётчик запросов через monkeypatch).

**Блок H — типы операций:** ADJUSTMENT оба знака; `is_skipped` не попадает в слой.

**Блок I — детач:** модель читаема после закрытия сессии (образец — `tests/test_serializers.py`).

**Блок J — fail-open:** monkeypatch-падение чтения бюджета → `degraded is True`, `goals_part == 0`, лог с трейсбеком; сумма слоёв по-прежнему == `balance`.

Итого ~37 тестов. Даты — относительные, `pytest.skip` не использовать (открытый вопрос №6 ROADMAP: самоотключение тестов уже стоило проекту 5 месяцев тихого падения покрытия).
