## Бизнес-процесс (контекст анализа)

**Entry point**: `run.py` → setup_logging → init_database → run_all_migrations (7 идемпотентных SQL-миграций через sqlite3) → auto_bootstrap (User по умолчанию + seed категорий) → app.run_server(:8050).

**Цепочка**: `app/main.py` (Dash init, глобальный layout: sidebar + page-content, глобальные модалы Transaction/Wishlist/Reconciliation/Onboarding/Profile, stores) → `display_page()` роутинг по url.pathname → страницы (dashboard / calendar / transactions / goals / analytics) → сервисный слой (15 сервисов, сессии через `get_db_session()`) → SQLAlchemy ORM → SQLite (`data/finfocus.db`).

**Завершение**: страница рендерится в page-content; дальнейшая работа через callbacks; обновления через Store-based refresh trigger pattern.

## Анализ кода

### Общий обзор

**Плюсы**:
- Архитектура из architecture.md реально соблюдается: слои Presentation/Service/ORM разделены, UI-компоненты не выполняют сырые SQL-запросы.
- `get_db_session()` (app/core/database.py) — эталонный контекстный менеджер (auto-commit/rollback/close), используется консистентно почти везде.
- Guard clauses (ADR-003) для pattern-matching callbacks применены системно и корректно (calendar, dashboard, transaction_modals, goals).
- Decimal-дисциплина сильная: деньги почти всегда Decimal; конвертация из UI через `Decimal(str(value))` — правильный паттерн, применён консистентно (float только на входе dbc.Input, что неизбежно для Dash).
- Хорошее тестовое покрытие (~553 теста, 36 файлов), включая миграции, сериализаторы, recurring-алгоритм.
- Сервисный слой чистый: валидация, русские docstrings, flush()/caller-commit по контракту.
- Идемпотентные миграции с проверками существования — разумно для MVP без Alembic.

**Минусы**:
- `app/components/goals.py` — God Module: ~4300 строк, 60+ функций, 5 бизнес-доменов в одном файле.
- Две разные стратегии сериализации Decimal→JSON в одном модуле serializers.py (str-based vs float-based).
- Подтверждённые UX-баги с ясной причиной в коде — прежде всего пробелы в проводке Store-триггеров.
- Логирование ошибок неоднородно (где-то exc_info=True, где-то без трейсбека, где-то except без логирования вовсе).

### Findings по аспектам

#### 🔴 Критично

**patterns / architecture** — `app/components/dashboard.py:84-91, 1336-1349, 1472-1508`; `onboarding_wizard.py:236`
Приветствие и баннер нулевого баланса не подписаны на Store `profile-updated` — нарушение собственного паттерна Selective Refresh (patterns/callbacks.md). Это причина UX-находки №1. Фикс: добавить Input("profile-updated","data") в load_dashboard_data и toggle_balance_toast (или вынести greeting в Store-управляемый callback).

**algorithms / errors** — `app/services/purchase_recommendation_service.py:66-70`
`except Exception: threshold = Decimal("0")` без логирования: при сбое CushionService сервис молча считает, что подушки нет, и выдаёт «безопасные даты» покупок fail-open. Финансово-значимая тихая деградация. Фикс: logger.warning(..., exc_info=True) + рассмотреть fail-closed.

#### 🟡 Внимание

- **code-smells / architecture** — `goals.py` (весь): God Module ~4300 строк, 5 доменов (Goals CRUD, Budget, Cushion, Redistribution, Contributions). Разбить на подпакет goals/ по доменам.
- **contracts / typing** — `serializers.py:65-97 vs 100-127`: две стратегии Decimal→JSON (str precision-safe vs float lossy) без задокументированного правила выбора. Унифицировать или задокументировать правило.
- **code-quality / dead-code** — `analytics_service.py:218-235`: end_of_month вычисляется дважды, первый блок с ошибочным hardcoded fallback 28 сразу перезаписывается правильным (calendar.monthrange); import calendar внутри цикла. Удалить мёртвый блок — мина при будущем рефакторинге.
- **patterns / dead-code** — `transaction_modals.py:616-622`: недостижимый try/except вокруг parse_date_safe (тот сам не рейзит). Убрать.
- **logging / errors** — dashboard.py:1505, transaction_modals.py:621 и др.: неоднородная практика логирования в except-блоках (exc_info / f-string без трейсбека / молчание). Ввести правило logger.exception().
- **algorithms** — `analytics_service.py:183-259`: get_monthly_trends делает N запросов (по одному на месяц). На текущем масштабе (SQLite, локально) несущественно — техдолг до многолетней аналитики.
- **patterns** — `goals.py:2246-2360`: callbacks возвращают 10-элементные tuple, дублируемые в каждой error-ветке. Ввести helper _goal_error_response() по образу _load_dashboard_components().

#### 🟢 Минорно

- **legacy** — `database.py:1-7`: TODO про Alembic — осознанный техдолг, отслеживать в ROADMAP к production.
- **code-quality** — `calendar_service.py:99` и др.: избыточные защитные `Decimal(str(...))` при Numeric-колонках. Не трогать.
- **security** — `run.py:58`: `host="0.0.0.0"` — локальное приложение с личными финансами слушает все интерфейсы без аутентификации. Сменить на 127.0.0.1, если не было осознанного решения (подтвердить у владельца).
- **dead-code / hygiene** — корень: FinFocus-v0.9.0-beta.1.zip, start_866.bat не в .gitignore (уже в «Открытых вопросах» ROADMAP, п.4).
