# FinFocus Knowledge Bank

**Knowledge Bank** — система документации проекта для AI агентов,
оптимизированная для быстрого понимания и поддержки. Живёт в
`.obsidian-docs/knowledge-bank/`.

## Что это?

Knowledge Bank обеспечивает:
- **Быстрое погружение** — 3-5 минут для понимания проекта
- **Актуальность** — регулярные обновления вместе с кодом
- **Краткость** — модули по 20-30 строк, детали — по ссылке
- **Полнота** — достаточно для работы без чтения всего кода

## Быстрый старт для AI

**При старте новой сессии (3-5 минут)**:
1. Прочитать `@ROADMAP.md` — актуальные приоритеты (единый источник правды)
2. Прочитать `@.obsidian-docs/reports/notes/feature_progress.md` — история последних батчей
3. Прочитать `knowledge-bank/index.md` — понять суть и статус проекта

**При работе над задачей**:
1. Определить тип задачи → прочитать соответствующий `modules/*.md`
2. Если новый паттерн → проверить `patterns/*.md` и `code-style.md`
3. Если изменение архитектуры → проверить `architecture.md`

## Принципы Knowledge Bank

### 1. Минимализм
- Краткие файлы модулей, детали — по ссылке, не в теле
- Только важная информация
- Ссылки на код вместо копирования

### 2. Актуальность
- Обновление вместе с кодом (после каждого протокола/батча)
- Удаление устаревшей информации, а не накопление
- Версионирование через git

### 3. Для AI, не для людей
- Структурированный формат
- Конкретные примеры кода
- Ссылки на файлы с номерами строк

### 4. Проверяемость
- Все утверждения проверяемы в коде
- Указание путей к файлам
- Примеры с реальным кодом

## Что НЕ документируем

❌ **Очевидные вещи** (Dash — это Python-фреймворк)
❌ **Дубли кода** (копирование целых файлов)
❌ **Изменчивые данные** (список всех операций пользователя)
❌ **Временные решения** (TODO-комментарии)

## Когда обновлять

**ОБЯЗАТЕЛЬНО**:
- После изменения архитектуры → `architecture.md`
- После добавления технологии → `tech-stack.md`
- После изменения стандартов → `code-style.md`
- После создания/изменения модуля → `modules/*.md`
- После нового протокола → `protocols.md` + `index.md` (статус)

**РЕКОМЕНДУЕТСЯ**:
- После каждого батча → `index.md` (прогресс)
- После багфикса → соответствующий модуль
- После рефакторинга → `architecture.md` (паттерны) или `patterns/*.md`

**НЕ НУЖНО**:
- После мелких изменений в коде
- После изменения UI текстов
- После обновления зависимостей (minor versions)
