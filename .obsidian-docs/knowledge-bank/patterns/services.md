# Паттерны работы с сервисным слоем

**Источник**: цикл проектирования куска 2 Epic-11 (протокол 0030,
solution v1-v4). Оба урока оплачены итерациями критики: первый — тремя
подряд правдоподобными, но неверными версиями расчёта «вчера» (в итоге
владелец убрал окошко «вчера» целиком), второй — блокером critique-v3.

## Урок 1. Два обязательных вопроса к оконному хелперу

Прежде чем передать оконному хелперу (функции, считающей значения для
СПИСКА дат) новую дату или расширенный список, ответить на два вопроса:

1. **Зависит ли результат от состава списка?** Хелпер вида
   `_payments_tail_by_day` накапливает суффиксную сумму ПРОХОДОМ по
   переданному списку: точечный вызов на одноэлементном списке вернёт
   ноль по построению — не потому что данных нет, а потому что
   накапливать не по чему. Такой хелпер зовут ОДИН раз на полном
   служебном списке, а не точечно на добавленной дате.

2. **Для каких дат выполняются его посылки?** Хелпер вида
   `_goals_part_by_day` берёт границы месяца по самому дню D — для дат
   за пределами окна, под которое он писался (например, «вчера» 1-го
   числа = чужой месяц), его посылки нарушаются, и он возвращает
   правдоподобный мусор (полный бюджет текущей настройки, отнесённый к
   прошлому месяцу). Инвариант суммы такие дефекты НЕ ловит: каскад
   сохраняет сумму при любом входе.

**Приём**: перед добавлением даты в расчёт — прочитать Note-секции
докстринга хелпера. В этом проекте вырожденные случаи документируются
именно там (пример: `_goals_part_by_day`, Note про committed на границе
месяца). Если Note молчит о вашей дате — проверить посылки по телу.

## Урок 2. Проверить `__init__` перед передачей сессии в конструктор

Не все сервисы проекта принимают сессию: `AllocationService` —
единственный stateless-сервис, у класса НЕТ `__init__`, он работает на
переданном списке ORM-объектов и конструируется БЕЗ аргументов.
`AllocationService(session)` даёт TypeError — и если вызов обёрнут
блочным try/except (композитор, fail-open коллбэк), ошибка молча
превращается в деградацию на ЛЮБЫХ данных, без единой строки в тестах,
которые кормятся словарями.

**Приём**: перед `SomeService(self.session)` — `grep "def __init__"
app/services/some_service.py` и взгляд на существующие вызовы. Плюс
целевой тест на «успешный путь» блока (goals=OK на фикстуре с целями,
протокол 0030): в наборе, где все фикстуры пустые, а тест деградации
ожидает FAILED как правильный ответ, неверный конструктор не краснит
ничего.

**Stateless НЕ значит «можно вне сессии»**: calculate_allocation читает
атрибуты живых ORM Goal — вызов обязан оставаться внутри открытой сессии.
