# Батч 0: Discovery & Foundation

**Продолжительность**: 3 недели  
**Тип**: Discovery + инженерные спайки  
**Цель**: Валидация концепции, архитектурные решения, первые прототипы

## Обоснование приоритета

Этот батч критически важен для снижения рисков разработки. Согласно dual-track agile, параллельные Discovery и Delivery на раннем этапе позволяют избежать дорогостоящих переделок в будущем. Event Storming и юзабилити-тесты вайрфреймов дадут понимание корректности доменной модели и пользовательских сценариев до начала основной разработки.

## Ключевые активности

### Неделя 1: Event Storming & Domain Modeling
**Участники**: Product Owner, UX, архитектор, 1-2 разработчика

**Результаты**:
- **Карта событий**: Доход получен, Расход создан, Цель добавлена, Взнос в цель рассчитан, Остаток пересчитан, Цель достигнута
- **Агрегаты и границы**: Финансовые операции, Кассовый календарь, Накопительные цели, Пользовательские настройки
- **Бизнес-правила**: Правила расчёта остатков, алгоритмы распределения по целям, логика повторяющихся операций
- **Спорные моменты**: Как обрабатывать перенос даты платежа? Что делать при недостатке средств для взноса?

**Инструменты**: Miro/Figma для Event Storming, документация в Notion/Confluence

### Неделя 2: Wireframes & User Testing  
**Участники**: UX дизайнер, Product Owner, 5-8 потенциальных пользователей

**Результаты**:
- **Low-fi вайрфреймы** основных экранов:
  - Дашборд (месячный/годовой вид)
  - Кассовый календарь с операциями
  - Форма добавления дохода/расхода
  - Создание цели накопления
  - Настройки режимов накоплений
- **Юзабилити-тесты**: 5-8 сессий по 30-45 минут
- **Отчёт по тестированию**: Выявленные проблемы навигации, понимания интерфейса
- **Итерированные вайрфреймы** с учётом обратной связи

**Критерии успеха тестов**:
- Пользователи понимают концепцию кассового планирования
- Создание цели занимает < 3 минут  
- Добавление операции в календарь интуитивно понятно

### Неделя 3: Technical Spikes & Architecture
**Участники**: Техлид, 2-3 разработчика

**Результаты**:
- **Spike 1: Cash Flow Engine**
  - Прототип расчёта остатков по датам с учётом повторяющихся операций
  - Покрытие тестами краевых случаев (выходные, переносы дат)
  - Оценка производительности на 1000+ операций
- **Spike 2: Goal Allocation Algorithm**  
  - Алгоритм расчёта взносов для одной цели по дедлайну
  - Базовая логика перераспределения при достижении цели
  - Юнит-тесты основных сценариев
- **Архитектурные решения**:
  - Технологический стек: React/Vue + Node.js/Python + PostgreSQL
  - Структура базы данных для операций и целей
  - Подход к кэшированию расчётов календаря
- **DevOps setup**: CI/CD pipeline, окружения dev/staging

**Технические критерии**:
- Корректный расчёт остатка на любую дату в диапазоне 2 лет
- Время расчёта месячного календаря < 100ms для 100 операций
- Архитектура поддерживает добавление новых типов операций

## Риски и митигация

### Высокие риски
- **Сложность кассового календаря**: Повторяющиеся операции + переносы + выходные
  - *Митигация*: Ранний spike с фокусом на краевые случаи, изучение библиотек для работы с датами
- **Пользователи не понимают концепцию**: Кассовое планирование не интуитивно
  - *Митигация*: Несколько итераций вайрфреймов, расширенное тестирование с объяснением ценности

### Средние риски  
- **Производительность расчётов**: Много операций + много дат = медленные вычисления
  - *Митигация*: Spike по производительности, рассмотрение кэширования и оптимизации
- **Техническая сложность алгоритмов**: Распределение по целям может оказаться сложнее ожидаемого
  - *Митигация*: Начать с простейшего случая одной цели, итеративное усложнение
