# Brief: Полоска-меню вместо сайдбара на не-дашборд экранах (Epic-11, кусок 3)

## Цель

Завершить замену каркаса навигации, начатую карточками-дверьми куска 2: широкая стеклянная карточка-сайдбар (288 px, профиль сверху, пять подписанных пунктов, «Настройки» и версия внизу) заменяется узкой вертикальной полоской иконок (60 px) на всех не-дашборд экранах. Дашборд остаётся единственной полноценной навигацией («щиток»); полоска — быстрый возврат на дашборд и переключение между четырьмя разделами, не отъедающее место у содержимого. Попутно закрываются два пункта UX-аудита 2026-08-20: P1 («Настройки» ведут на 404 — пункт убирается) и P3 (зашитая «v1.0.0» — версия переезжает в окно профиля и берётся из проекта).

## Функциональные требования

- **FR-1.** Узкая вертикальная полоска иконок слева (60 px) на всех не-дашборд экранах. Сверху — знак-логотип домик `bi-house-door`, ведущий на дашборд, визуально выделенный (44×44, radius 12px, градиент бренда, знак 24px белый). Ниже — иконки четырёх разделов (Календарь, Операции, Аналитика, Цели), слот 44×44, шаг 7px, знак 22px. Внизу — аватар пользователя (круг 44×44), прижатый распоркой. Подписи разделов раскрываются язычком при наведении. Активный раздел подсвечен пилюлей.
- **FR-2.** При входе в раздел С ДАШБОРДА полоска анимированно разворачивается сверху вниз (~220 мс, CSS-переход высоты кожуха). При переходах МЕЖДУ разделами анимация не переигрывается. У пунктов собственной анимации нет.
- **FR-3.** Прежний сайдбар (`create_sidebar`, `.sidebar-card`, «профиль сверху») удаляется со всех экранов. Открытие окна профиля кликом по аватару сохраняется.
- **FR-4.** Пункт «Настройки» в полоску не переносится. Попасть на несуществующий `/settings` из навигации становится нельзя.
- **FR-5.** Номер версии в навигации не отображается; он показывается в окне профиля и берётся из проекта, а не зашитой строкой. Источник версии в проекте отсутствует — его надо завести, устойчиво к запуску из PyInstaller-бандла.

## Нефункциональные требования

- **NFR-1.** Компонент полоски не обращается к БД на построении — профиль приходит аргументом (наследуется от куска 2).
- **NFR-2.** Разворот уважает `prefers-reduced-motion: reduce`: перехода нет, конечное состояние достигается сразу. Образец применения уже есть в `panel.css` (строки 282, 830).
- **NFR-3.** Переход между разделами не становится заметно медленнее текущего (ориентир куска 2 — построение навигации порядка единиц миллисекунд).
- **NFR-4.** Каждая иконка имеет доступное текстовое имя (`aria-label`); активный пункт помечен `aria-current="page"`. Язычок при наведении не может быть единственным носителем смысла.

## Ограничения

- **C-1.** У модуля компонента навигации — ни одного серверного обработчика (`@callback`). Всё приходит аргументами и вычисляется на построении.
- **C-2.** Скрытие колонки — ровно одно правило CSS `:empty`. Второй механизм (переключение класса обработчиком) не вводить.
- **C-3.** Вход в окно профиля — только через Store-триггер (`open-profile-trigger`), прямая привязка ломала колбэк дважды (протоколы 0026, 0028).
- **C-4.** Владение `url.search` не меняется: `/transactions` принадлежит фильтру периода (протокол 0023), `_OWNED_SEARCH_PATHS` остаётся `{"/calendar", "/goals"}`.
- **C-5.** Дашборд остаётся без навигации слева — полоска на нём не появляется.
- **C-6.** Набор разделов не меняется: те же пять маршрутов. Дашборд представлен логотипом, четыре раздела — иконками.
- **C-7 (наследуемое).** Мёртвая константа `ADDITIONAL_NAV_ITEMS` («Справка» → `/help`) не трогается — решение владельца, вне рамок куска 3.

## Критерии приёмки

- [ ] **AC-1.** На любом не-дашборд экране слева видна узкая полоска иконок; широкой карточки со списком подписанных пунктов на странице нет.
- [ ] **AC-2.** На дашборде слева нет ни полоски, ни сайдбара, и место под них не занято пустой колонкой.
- [ ] **AC-3.** При наведении на иконку раздела появляется подпись раздела (язычок).
- [ ] **AC-4.** Иконка текущего раздела визуально отличается от остальных; при переходе подсветка переезжает.
- [ ] **AC-5.** Переход с дашборда в раздел → полоска разворачивается сверху вниз. Переход из раздела в другой раздел → разворот не повторяется.
- [ ] **AC-6.** При включённой системной настройке «уменьшить движение» полоска сразу показана целиком, без анимации.
- [ ] **AC-7.** Клик по аватару внизу полоски открывает окно профиля — проверено на КАЖДОМ из четырёх разделов, а не на одном.
- [ ] **AC-8.** Клик по логотипу вверху полоски ведёт на дашборд.
- [ ] **AC-9.** В навигации нет ни «Настроек», ни номера версии. Номер версии виден в окне профиля и совпадает с реальной версией проекта.
- [ ] **AC-10.** Переходы с контекстом куска 2 работают: `?focus_date=`, `?goal=`, `?wishlist_item=`, `?open_recon=1`.
- [ ] **AC-11.** У модуля компонента навигации нет ни одного серверного обработчика — проверяется тестом-якорем.

## Вне scope (out of scope)

- Мобильная адаптация (превращение полоски в нижнюю панель) — Epic-08. Не делать, но и не блокировать архитектурно.
- Анимация перехода дашборд↔раздел («перелистывание») — Epic-10.
- Страница `/settings` — пункт убирается, страница не создаётся.
- Мёртвая константа `ADDITIONAL_NAV_ITEMS` — не трогается.
- Отклонённые в design.md альтернативы навигации (верхняя полоска, «только через дашборд», скрытое меню) — к пересмотру не предлагать.
- Пересмотр содержимого разделов.
- Автоматизация бампа версии в CI, синхронизация версии с git-тегом при сборке.
