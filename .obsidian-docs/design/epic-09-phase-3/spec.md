# Spec: Epic-09 Phase 3 — Delivery & Setup for Beta Testers

## Цель
Обеспечить нетехническим пользователям возможность установить и запустить FinFocus на своём компьютере без помощи разработчика. Один скрипт: скачал → запустил → работает.

## Контекст

### Текущее состояние
- **Запуск**: `python run.py` — требует установленного Python, pip install, знания терминала
- **run.py**: инициализирует БД, миграции, auto-bootstrap, запускает Dash сервер на `localhost:8050`
- **requirements.txt**: 12 зависимостей (dash, sqlalchemy, plotly, loguru и др.)
- **БД**: SQLite `data/finfocus.db` — создаётся автоматически, не требует настройки
- **Конфигурация**: переменные окружения `PORT` (default 8050) и `DEBUG` (default False), .env не используется
- **Auto-bootstrap**: создаёт User(id=1) и seed-категории при первом запуске — cold start готов
- **Python version**: >= 3.10 (в проекте используется 3.12)
- **Проект НЕ опубликован** на PyPI

### Целевая аудитория
- Нетехнические пользователи (не знают терминал, pip, venv)
- Платформы: Linux, Windows, macOS
- Получают приложение: скачивают zip с GitHub Releases или получают файл лично

### Ключевые ограничения
- Приложение работает в браузере (localhost:8050) — это веб-приложение на Dash
- Нативное окно (flaskwebgui) отложено в Backlog
- Python должен быть установлен на машине пользователя (setup-скрипт проверяет и подсказывает)
- Docker НЕ используется (слишком сложен для целевой аудитории)
- PyInstaller НЕ используется (сложная сборка Dash на 3 платформы, отложено в Backlog)

## Требования

### R1: Start-скрипт для Linux/macOS (`start.sh`)
- Bash-скрипт с `#!/bin/bash`
- Проверяет наличие Python 3.10+ (`python3 --version`)
- Если Python не найден — выводит понятную инструкцию по установке (ссылки для каждой ОС)
- Создаёт venv (если не существует) в директории проекта
- Устанавливает зависимости из `requirements.txt` (pip install -r)
- Запускает `run.py`
- Автоматически открывает браузер на `http://localhost:8050` (через `xdg-open` / `open`)
- При повторном запуске — пропускает создание venv и установку, если уже есть
- Выводит понятные сообщения о прогрессе на русском языке

### R2: Start-скрипт для Windows (`start.bat`)
- Batch-скрипт для cmd.exe
- Аналогичная логика: проверка Python → venv → pip install → запуск → открытие браузера
- `start http://localhost:8050` для открытия браузера
- Понятные сообщения на русском

### R3: BETA_README.md
- Инструкция для тестера на русском языке
- Максимум 3 шага: 1) Установить Python 2) Запустить скрипт 3) Пользоваться
- Ссылка на скачивание Python для каждой ОС
- Раздел "Частые проблемы" (FAQ): Python не найден, порт занят, как остановить
- Раздел "Как сообщить о проблеме" (скриншот + описание → автору)
- Без технического жаргона

### R4: Проверка requirements.txt
- Убрать dev-зависимости (pytest, pytest-cov, black, flake8) из основного файла
- Создать `requirements-dev.txt` для разработчиков (включает основной + dev tools)
- В start-скриптах использовать `requirements.txt` (только runtime)

### R5: GitHub Release (документация процесса)
- Описать процесс создания Release в BETA_README.md или отдельном файле
- Tag format: `v0.9.0-beta.1`
- Release notes шаблон
- Zip-архив с исходным кодом (GitHub создаёт автоматически)

## Критерии приёмки
- [ ] `start.sh` запускает приложение на Linux/macOS при наличии Python 3.10+
- [ ] `start.bat` запускает приложение на Windows при наличии Python 3.10+
- [ ] При отсутствии Python — понятное сообщение с инструкцией
- [ ] Повторный запуск быстрый (не пересоздаёт venv)
- [ ] BETA_README.md понятен нетехническому пользователю
- [ ] requirements.txt содержит только runtime-зависимости
- [ ] Существующие тесты проходят (`pytest -k "not test_budget_change_updates_allocation"`)
- [ ] `black app/` + `flake8 app/` без ошибок
