# EPIC-11 «Щиток», кусок 2: карточки-двери (ЗАГОТОВКА)

> **Очередь:** после батча куска 1 (`../epic-11-panel-batch-1/spec.md`);
> заготовка, доработать через /spec-prep перед запуском.
> Источник правды — design.md обсуждения dashboard-as-menu-2026-08-23.

## Цель

Дашборд становится навигацией: карточки — живые фрагменты разделов и
единственная точка входа в них (метафора электрощитка), меню с дашборда
убирается. Клик по карточке — переход в раздел с сохранением контекста.

## Черновые требования

- **FR-1.** Карточки-двери по принятой проекции разделов (design.md):
  Календарь (вчера/сегодня/завтра + маркер просадки), Цели (топ-цель +
  сводка + статус подушки внутри), Операции (2-3 недавние + 2-3
  предстоящие), Аналитика (цифра месяца), Wishlist (компактный виджет);
  Настройки — служебная иконка, не карточка.
- **FR-2.** Конституция щитка: каждый предметный пункт меню имеет
  карточку; на дашборде меню нет — сайдбар с дашборда убирается.
- **FR-3.** Переход с сохранением контекста (клик по «завтра» →
  календарь на завтра; клик по цели → цели с фокусом на ней; операции →
  список с фильтром периода; аналитика → текущий месяц).
- **FR-4.** Пристройство оставшихся механик-сирот текущего дашборда:
  онбординг-тост нулевого баланса (и прочее по инвентаризации ревью
  2026-08-23, за вычетом закрытого в куске 1).
- **FR-5.** Пустые состояния карточек у нового пользователя — первое
  впечатление беты.
- **FR-6.** Стратегия загрузки: фрагменты всех разделов = данные всех
  страниц при каждом открытии — нужна стратегия (кеш, ленивая
  подгрузка); карточки питаются единой моделью куска 1, где применимо.

## Заметки

- Промежуточное состояние принято: дашборд без меню, остальные разделы
  ещё со старым сайдбаром (полоска — кусок 3).
- Данные карточек не должны противоречить шапке/графику — единая модель
  (осадок epic-11, P1-боль аудита).
