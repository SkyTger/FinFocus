# Brief: Карточки-двери щитка (Epic-11, кусок 2)

## Цель

Превратить дашборд FinFocus в единственную навигацию по предметным разделам: под уже существующей шапкой «Свободно сегодня» и графиком полос (кусок 1) появляется ряд карточек-дверей — живых фрагментов разделов (Календарь, Цели, Операции, Аналитика, Wishlist). Сайдбар с дашборда убирается; клик по элементу карточки открывает раздел в состоянии, соответствующем клику. Разделы содержательно не пересматриваются — только минимальные приёмники контекста.

## Функциональные требования

- **FR-1. Пять карточек-дверей по принятой проекции разделов.**
  - **Календарь**: вчера / сегодня / завтра — остатки дней; маркер просадки — день минимума слоя «Свободно» в окне модели, показывается всегда; при минимуме ≤ 0 маркер визуально усиливается (факт знака, не порог-вердикт). Дверь: календарь на кликнутом дне.
  - **Цели**: топ-цель с прогрессом, сводка остальных («по плану / 1 отстаёт»), статус подушки одной строкой (отдельной карточки подушки нет). Дверь: `/goals` с фокусом на кликнутой цели.
  - **Операции**: 2–3 недавние + 2–3 предстоящие. Дверь: `/transactions` с фильтром периода.
  - **Аналитика**: цифра месяца — расходы месяца, топ-категория расходов, мини-структура. Показатель «Доходы за месяц» НЕ возвращается ни в каком виде. Дверь: `/analytics` на текущем месяце.
  - **Wishlist**: компактный виджет. Дверь двухуровневая: заголовок/тело → модал управления wishlist; клик по конкретной хотелке → календарь в режиме покупок с фокусом на ней.
  - **Настройки**: служебная шестерёнка шапки (есть с куска 1), не карточка.
- **FR-2. Конституция щитка.** Каждый предметный пункт меню имеет карточку; сайдбар убирается с дашборда и остаётся на `/calendar`, `/goals`, `/transactions`, `/analytics`.
- **FR-3. Переход с сохранением контекста.** «Завтра» → календарь на завтрашнем дне; цель → фокус на ней; операции → фильтр периода; аналитика → текущий месяц. Позиционная привязка фрагмента не требуется («дух важнее буквы»).
- **FR-4. Механики-сироты.** Онбординг-тост нулевого баланса сохраняет поведение на перестроенном дашборде.
- **FR-5. Пустые состояния.** При 0 операций / 0 целей / пустом wishlist все пять карточек остаются на месте и показывают спроектированные пустые состояния без числовых артефактов.
- **FR-6. Единая модель и явная стратегия загрузки.** Карточка «Календарь» питается моделью слоёв куска 1; цифры карточек не противоречат шапке и графику. Стратегия загрузки (число вызовов, число сессий, кеш/ленивость) проектируется явно под бюджет NFR-1.

## Нефункциональные требования

- **NFR-1. Производительность.** Открытие дашборда со всеми карточками на наполненной локальной базе — < 2 секунд (ориентир ROADMAP; кусок 1 давал 13 мс на 120 операциях, деградация должна быть объяснима).
- **NFR-2. Наблюдаемость и деградация.** Сбой сборки данных одной карточки не обрушивает дашборд: карточка деградирует с индикацией, сбой логируется через `logger.opt(exception=True)`. Сбой расчёта базовой модели остатка не глотается.

## Ограничения

- **C-1.** Разделы содержательно не пересматриваются; допустимы только минимальные приёмники контекста FR-3.
- **C-2.** Дисциплина сервисного слоя: Decimal, session-контракт flush()/commit(), сервисы не знают о Dash.
- **C-3.** Поведение существующих сервисов не меняется; полный прогон 693 тестов остаётся зелёным.
- **C-4.** Схема БД не меняется.
- **C-5.** Контракт `MoneyLayersService`/`MoneyLayersData` менять МОЖНО, но шапка и график продолжают работать, инвариант «сумма слоёв == остаток кассового календаря» сохраняется.
- **C-6.** Новые интерактивные элементы дашборда — только через Store-триггеры: прямой Input на элемент, существующий только на дашборде, молча отключает колбэк на всех остальных страницах.
- **C-7.** Шапка и график куска 1 визуально и поведенчески не регрессируют; 47 тестов визуального слоя щитка зелёные или осознанно адаптированы.

## Критерии приёмки

- **AC-1.** Наполненная база, открыт `/dashboard` → видны карточки пяти разделов; сайдбара нет; на `/calendar`, `/goals`, `/transactions`, `/analytics` сайдбар есть.
- **AC-2.** Клик «завтра» → календарь с завтрашним днём; клик по цели → `/goals` с фокусом на ней; клик по операциям → `/transactions` с фильтром периода; клик по карточке Аналитика → `/analytics` с данными текущего месяца.
- **AC-3.** Остаток «сегодня» в карточке Календарь равен значению модели слоёв на сегодня (тому же, из которого построена шапка) — unit-тест.
- **AC-4.** Карточка Цели содержит топ-цель с прогрессом, сводку остальных и строку подушки; отдельной readonly-карточки подушки нет; split-таблицы операций заменены карточкой Операции.
- **AC-5.** Чистая база → все пять карточек на месте с пустыми состояниями без числовых артефактов.
- **AC-6.** Онбординг-тост нулевого баланса появляется и ведёт себя как до перестройки.
- **AC-7.** Минимум «Свободно» > 0 → день минимума без усиления; минимум ≤ 0 → маркер усилен — unit-тесты.
- **AC-8.** Клик по заголовку/телу карточки Wishlist → модал управления; клик по конкретной хотелке → календарь в режиме покупок с фокусом на ней.
- **AC-9.** Модал профиля открывается со всех страниц обоими входами (аватар сайдбара вне дашборда, шестерёнка шапки на дашборде) — регрессии C-6 нет.
- **AC-10.** Новые данные и UI покрыты unit-тестами; полный pytest зелёный; black + flake8 без новых замечаний; рендер дашборда в NFR-1.

## Вне scope (out of scope)

- Полоска-меню вместо сайдбара на остальных страницах и её анимация — кусок 3.
- Анимация переходов дашборд↔раздел — Epic-10.
- Мобильная адаптация щитка и карточек — Epic-08.
- Настраиваемость дашборда, механика «основного дохода» — законсервированы.
- Содержательный пересмотр разделов, включая выбор произвольного месяца в аналитике.
- Возврат показателя «Доходы за месяц» в любом виде.
- Жизненный цикл целей (превышение, просроченные).
- Раздел `/settings` — заглушка остаётся.
- Вердикт безопасности покупки («безопасно после N») в карточке Wishlist — `PurchaseRecommendationService.get_safe_dates_map` считает по всему месяцу и не укладывается в бюджет карточки; вердикт остаётся в режиме покупок календаря.
