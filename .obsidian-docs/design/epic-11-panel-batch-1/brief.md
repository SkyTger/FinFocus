# Brief: EPIC-11 «Щиток», кусок 1 — модель «свободно/платежи/резерв», шапка-вердикт, график полос

## Цель

Главный экран FinFocus должен за 5 секунд отвечать на вопрос «сколько у меня реально свободных денег и что впереди». Для этого вводится единая сервисная модель декомпозиции прогнозного остатка на три именованных слоя (Свободно / Платежи / Резерв) по дням текущего календарного месяца, а дашборд получает построенные поверх неё шапку-вердикт и график полос — с полным вытеснением текущего ряда 4 KPI-карточек и текущего графика grouped bars + линия баланса. Модель — единственный источник цифр для шапки и графика, что устраняет P1-боль UX-аудита 2026-08-20 «цифры соседних карточек противоречат друг другу».

## Функциональные требования

- **FR-1.** Сервисная модель «свободно/платежи/резерв» по дням: для каждого дня горизонта (от сегодня до конца текущего календарного месяца) декомпозиция прогнозного остатка на три слоя — *Свободно* (реально доступные деньги), *Платежи* (деньги ещё на счету, но уйдут на запланированные регулярные + разовые платежи до конца календарного месяца; слой «тает» по мере исполнения платежей и пересчитывается на границе месяца), *Резерв* (резерв целей + подушка). Сумма трёх слоёв на день D равна прогнозному остатку на D из кассового календаря (CalendarService).
- **FR-2.** Шапка-вердикт вверху дашборда: «Свободно сегодня: N ₽» (N — срез модели на сегодня), цветовой вердикт состояния (порядок / впереди просадка / проблема), краткий разбор «баланс − платежи − резерв». Справа — аватар пользователя и служебная иконка настроек. Шапка не является дверью-переходом. Шапка **заменяет** текущий ряд 4 KPI-карточек.
- **FR-3.** График полос вместо текущего графика (grouped bars + линия баланса, протокол 0022) — заменяется полностью: стопка полос Свободно (зелёный) / Платежи (оранжевый) / Резерв (синий) по дням, вехи целей на оси времени, вертикальная линия «сегодня», маркер минимума остатка. График и шапка — единый визуальный блок: «свободно сегодня» есть срез графика на сегодня.
- **FR-4.** Тултип-пояснение легенды: для «Платежей» — список конкретных предстоящих платежей с датами («аренда 25 авг, коммуналка 28 авг…»); для «Свободно» и «Резерва» — что входит в слой.
- **FR-5.** Пристройство механик вытесняемого KPI-ряда: вход в «Сверку» с дашборда сохраняется; судьба показателя «Доходы за месяц» решена явно (сохранён в новом месте или убран осознанно).
- **FR-6.** Пустые состояния: при нулевых данных (новый пользователь, 0 операций) шапка и график показывают спроектированное пустое состояние без осей −1..1, склеек подписей и прочих артефактов деградации.

## Нефункциональные требования

- **NFR-1.** Загрузка дашборда с новой моделью и графиком не медленнее текущего; ориентир — < 2 секунд на локальной базе с наполненными данными.
- **NFR-2.** Сбои расчёта модели логируются через loguru с трейсбеком (`logger.opt(exception=True)`), не молча.

## Ограничения

- **C-1.** Остальные разделы (календарь, цели, операции, аналитика) и сайдбар не трогаются. Таблицы операций, wishlist-виджет и карточка подушки на дашборде остаются как есть.
- **C-2.** Дисциплина сервисного слоя: Decimal для денег, session-контракт flush()/commit(), сервисы не знают о Dash.
- **C-3.** Существующее поведение сервисов не меняется — модель FR-1 строится надстройкой/композицией; полный прогон тестов (565) остаётся зелёным.
- **C-4.** Схема БД не меняется.
- **C-5.** Горизонт слоя «Платежи» — до конца календарного месяца. Механику «основного дохода» не реализовывать.

## Критерии приёмки

- [ ] **AC-1.** Наполненная база → на дашборде видна шапка «Свободно сегодня: N ₽» с цветовым вердиктом и разбором, N совпадает со значением слоя «Свободно» модели на сегодняшнюю дату (срез графика).
- [ ] **AC-2.** Отображается график стопки трёх полос с легендой «Свободно / Платежи / Резерв», вехами целей, линией «сегодня» и маркером минимума; старый график доходы/расходы+баланс и ряд 4 KPI-карточек отсутствуют.
- [ ] **AC-3.** Для любого дня D горизонта сумма трёх слоёв модели равна прогнозному остатку на D из кассового календаря (CalendarService) — проверено unit-тестом.
- [ ] **AC-4.** Наведение/клик на пояснение легенды «Платежи» показывает список конкретных предстоящих платежей с датами до конца месяца.
- [ ] **AC-5.** Чистая база (онбординг пропущен, 0 операций) → шапка и график показывают осмысленное пустое состояние без артефактов (осей −1..1, «50.001k», склеек подписей).
- [ ] **AC-6.** Вход в сверку с дашборда работает: модал сверки открывается и применяется, как до редизайна.
- [ ] **AC-7.** Новая модель покрыта unit-тестами (включая границу месяца и «таяние» платежей); полный прогон pytest зелёный; black + flake8 без новых замечаний.

## Вне scope (out of scope)

- Карточки-двери, конституция щитка, переходы с сохранением контекста, онбординг-тост, стратегия загрузки/кеширования фрагментов — кусок 2.
- Полоска-меню вместо сайдбара, анимация разворачивания — кусок 3.
- Анимация переходов дашборд↔раздел — Epic-10.
- Мобильная адаптация щитка — Epic-08.
- Механика «основного дохода», настраиваемость дашборда — законсервированы.
- Жизненный цикл целей (превышение, просроченные) — отдельная проработка.
- Возврат старого графика внутри какого-либо раздела.
