# Досье: дашборд как меню («щиток») (2026-08-23)

> Досье для агента second-opinion. Правила: только факты, решения и
> их обоснования — без оценок и выводов. Дописывается в момент
> выжимки; после автокомпакта — перечитать и продолжить с пустого
> раздела.

## Идея и цель

Владелец FinFocus (приложение планирования личного бюджета: кассовый
календарь + накопительные цели) предложил редизайн: вместо бокового
меню сам дашборд становится навигацией. Метафора электрощитка:
лицевая панель с «прорезями»-карточками, через которые видны живые
фрагменты разделов; клик по карточке («открытие панели») ведёт в
полный раздел с сохранением контекста. Цель — дашборд, отвечающий на
главный вопрос за 5 секунд, и навигация без отдельного меню на
главном экране.

## Проблема и её свидетельства

- UX-аудит 2026-08-20 (независимый прогон глазами нового
  пользователя): дашборд — самый слабый раздел, «не отвечает ни на
  один вопрос за 5 секунд», график требует обучения; владелец
  подтвердил («то, что сразу закроешь»).
- P1 аудита: цифры соседних карточек противоречат друг другу на глаз
  («Доходы 247 000» рядом с «Нет операций за период»; «Накопления 0%
  из 207 000» рядом с «Подушка: 922 155 из 100 000»).
- P1 аудита: продукт не объясняет свои понятия (нет подсказок у
  «Сверки», «Подушки», режимов накоплений).
- Полный список решений и статусы — ROADMAP, секция «UX-аудит
  2026-08-20» и «Открытые вопросы» (№7 — переосмысление дашборда,
  №9 — «доработка инструмента вместо заплаток»).

## Ключевые решения и их обоснования

Все 18 решений с обоснованиями зафиксированы в
`.obsidian-docs/discussions/dashboard-as-menu/WIP.md` (секция «Что
РЕШЕНО») — первоисточник, не дублируется здесь. Скелет:

1-4: дух важнее буквы (позиционная привязка — не требование); на
дашборде меню нет совсем; на остальных экранах компактное; масштаб —
редизайн дашборда, не всей навигации.
5: настраиваемость дашборда отложена в пользу сильного дефолта.
6: главный ответ за 5 секунд — «Свободно сегодня: N ₽» + цветовой
вердикт.
7: «конституция щитка» — каждый пункт меню обязан иметь
карточку-представительство; иерархия определяет размер/позицию, но
не присутствие.
8: проекция разделов на щиток принята (календарь: вчера/сегодня/
завтра; цели: топ-цель + сводка + подушка внутри; операции: недавние
+ предстоящие; аналитика: цифра месяца; wishlist: виджет; настройки:
служебная иконка, не карточка).
9-10: график «деньги с именами» (полосы свободно/платежи/резерв с
вехами целей) — центральный элемент, единый блок с шапкой; старый
график (бары+линия) заменяется полностью.
11: эскиз собран через /visual, вердикт SHIP.
12-15: семантика полосы платежей; тултип-пояснение легенды; горизонт
расчёта — до конца месяца (механика «основного дохода»
законсервирована); легенда финальная: Свободно / Платежи / Резерв
целей и подушки.
16: компактное меню — вертикальная полоска иконок ~60px слева,
автоматический анимированный разворот из логотипа при входе в раздел.
17: анимация переходов — первая версия без эффектов; кандидат на
полировку: «перелистывание» (дешёвая версия — въезд нового экрана).
18: раскладка 8/4 закрыта — новая структура её заменяет.

## Осознанно отброшенное (с причинами)

- Позиционная привязка «фрагмент ровно там же, где в полном разделе»
  как жёсткое требование — конфликт с приоритетной раскладкой,
  скроллящиеся страницы, мобильная адаптация (решение 1).
- Настраиваемость дашборда как замена сильного дефолта — большинство
  не меняет дефолты; «разные приоритеты» — один пользователь в
  разные моменты (решение 5).
- Название «Обещано», затем «Зарезервировано» для оранжевой полосы —
  первое непонятно (владелец сам споткнулся), второе коллизирует с
  «Резервом целей и подушки» (решение 15).
- Горизонт «до следующего основного дохода» как основной — сложнее и
  дольше; выбран «до конца месяца», механика основного дохода
  законсервирована; известное ограничение: платежи начала следующего
  месяца до зарплаты не видны (решение 14).
- Верхняя полоска меню (съедает высоту), «вся навигация через
  дашборд» (два клика на переход), скрытое меню по клику/ховеру
  (находимость, мобильные) (решение 16).
- Shared-element анимация «карточка вырастает в страницу» — дорого и
  хрупко в Dash (решение 17).
- Полная карусель «оба экрана летят» при перелистывании — хак в Dash
  (решение 17).

## Ограничения и контекст

- Стек: Python/Dash (server-rendered, переходы страниц перерисовывают
  контент целиком) + Plotly; SQLite; 565 unit-тестов.
- Владелец — PM/вайбкодер: направляет работу, код не пишет.
- Стадия продукта: v0.9.0-beta.1, идёт подготовка к бета-тестированию
  (Epic-09, фаза Bug fixes & Polish не начата).
- В сервисах нет модели «свободно/платежи/резерв» — только
  доходы/расходы/баланс; модель признана ядром будущих работ.
- Запланированы, но не начаты: Epic-10 (полировка UI, design tokens),
  Epic-07 (тёмная тема), Epic-08 (мобильная адаптация).
- Открытые инженерные вопросы обсуждения (не решались сознательно):
  модель данных, стратегия загрузки дашборда, мобильная адаптация,
  оформление эпиком/увязка с №9 — см. «Что ОТКРЫТО» в WIP.
