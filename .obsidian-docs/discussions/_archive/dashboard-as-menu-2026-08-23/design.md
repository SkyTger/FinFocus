# Дашборд как меню («щиток») — финальный дизайн

> Финал обсуждения, закрытого 2026-08-23. Источник правды по теме.
> Если правка — править дизайн, а не разводить новое обсуждение,
> пока не появится принципиально новый угол.

## Цель

Переосмыслить главный экран FinFocus: вместо «бокового меню + витрины
со сводкой» дашборд сам становится навигацией — по метафоре
электрощитка (лицевая панель с прорезями-карточками, через которые
видны живые фрагменты разделов; клик — «открытие панели» в полный
раздел). Решали две боли UX-аудита 2026-08-20: дашборд не отвечает ни
на один вопрос за 5 секунд, и цифры соседних карточек противоречат
друг другу. Закрывает открытый вопрос №7 ROADMAP («деньги с именами»)
и дашборд-часть вопроса №9 («доработка инструмента вместо заплаток»).

## Ядро концепции

**Дух важнее буквы**: позиционная привязка «фрагмент ровно там же, где
в полном разделе» — не требование (конфликтует с приоритетной
раскладкой, скроллом и мобильной адаптацией). Ядро — карточки как
живые фрагменты разделов + переход с сохранением контекста (клик по
«завтра» в мини-календаре открывает календарь на завтра).

**Конституция щитка**: каждый предметный пункт меню обязан иметь
карточку-представительство на дашборде — на дашборде меню нет,
карточки и есть навигация. Иерархия ответов определяет размер и
позицию карточки, но не факт присутствия. Правило распространяется и
на будущие разделы (импорт, уведомления): новый раздел = новая
карточка = пересмотр раскладки — осознанная цена. Служебные экраны без
предметного содержания (настройки, справка) — иконки, не карточки.

**Настраиваемость дашборда отложена** в пользу сильного дефолта
(большинство пользователей не меняют дефолты; «разные приоритеты» —
один пользователь в разные моменты). Беклог без обязательств.

## Иерархия внимания и состав щитка

Три уровня:

1. **Шапка-вердикт (5 секунд)**: «Свободно сегодня: N ₽» + цветовой
   вердикт (порядок / впереди просадка / проблема) + разбор «баланс −
   платежи − резерв целей». Справа — аватар и служебная иконка
   настроек. Не дверь.
2. **График «деньги с именами» (30 секунд)**: единый блок с шапкой —
   «свободно сегодня» есть срез графика на сегодня.
3. **Карточки-двери** — принятая проекция разделов:
   - **Календарь** → вчера/сегодня/завтра + маркер ближайшей просадки;
     дверь: календарь на кликнутом дне;
   - **Цели** → топ-цель с прогрессом + сводка остальных («по плану /
     1 отстаёт») + статус подушки одной строкой (подушка живёт внутри
     этой карточки, отдельной не имеет); дверь: цели с фокусом на
     кликнутой;
   - **Операции** → 2-3 недавние + 2-3 предстоящие; дверь: список
     операций с фильтром периода;
   - **Аналитика** → цифра месяца (топ-категория расходов +
     мини-структура); дверь: аналитика текущего месяца;
   - **Wishlist** → компактный виджет (не пункт меню,
     представительство сохраняется); дверь: модал/режим покупок;
   - **Настройки** → служебная иконка, не карточка (раздел отложен).

## Центральный график и его язык

Старый график (бары доходов/расходов + линия баланса на двух осях)
**заменяется полностью**; при желании позже возвращается внутри
раздела. Новый — декомпозиция прогнозного остатка по дням в стопку
полос, легенда финальная:

- **Свободно** (зелёный) — реально доступные деньги;
- **Платежи** (оранжевый) — деньги ещё на счету, но уйдут на уже
  запланированные платежи (регулярные + разовые предстоящие); полоса
  тает по мере исполнения платежей и пересчитывается на границе
  месяца;
- **Резерв целей и подушки** (синий).

Плюс вехи целей на оси времени, линия «сегодня», маркер минимума.
Название «Зарезервировано» для оранжевой отброшено (коллизия двух
«резервов» в одной легенде), «Обещано» — непонятно без пояснения.

**Тултип-пояснение у легенды** обязателен: конкретика платежей
(«аренда 25 авг, коммуналка 28 авг…») — закрывает часть P1 аудита
«продукт не объясняет себя».

**Горизонт «Платежей» — до конца календарного месяца** (проще и
быстрее). Осознанное ограничение: платежи начала следующего месяца до
зарплаты (резерв 1-го при зарплате 5-го) не видны в резерве текущего —
вспомнить при жалобах беты. Механика «основного дохода» (пометка
дохода, после которого обновляются расчёты; кейс «аванс + зарплата»)
законсервирована как будущее уточнение горизонта.

## Навигация вне дашборда

Компактное меню на всех не-дашборд экранах: узкая вертикальная полоска
иконок слева (~60px), подписи при ховере; сверху логотип-«щиток»
(возврат на дашборд, выделен), внизу аватар; активный раздел
подсвечивается. При входе в раздел полоска автоматически анимированно
разворачивается из логотипа вниз («открытие панели»); при переходах
между разделами не переигрывается; уважает prefers-reduced-motion.
Технически дёшево (CSS-переход). Отклонены: верхняя полоска (съедает
высоту), «вся навигация через дашборд» (два клика на переход), скрытое
меню по клику/ховеру (находимость, мобильные). На мобильных (Epic-08)
полоска превращается в нижнюю панель иконок.

## Анимация переходов

Первая версия — без эффектов. Кандидат на этап полировки (Epic-10):
«перелистывание» — дашборд улетает влево, раздел въезжает справа
(назад — наоборот); реализовывать дешёвую версию (въезд нового экрана,
чистый CSS поверх роутинга), полную карусель «оба экрана летят» — не
делать (хак в Dash). Откладывание не удорожает доработку.
Shared-element «карточка вырастает в страницу» отклонена окончательно.

## Масштаб и секвенирование

Честная формулировка объёма (для нарезки эпика): **редизайн дашборда +
замена каркаса навигации всех экранов** (сайдбар с динамическим
профилем из Epic-09 фазы 2 заменяется полоской на каждом экране).
Прочие разделы содержательно не пересматриваются.

**Сначала редизайн, бета потом** (владелец, 2026-08-23): редизайн
доводится до рабочего состояния до бета-цикла — бета идёт уже на новом
дашборде; сдвиг бета-релиза — осознанная цена (фидбек не тратится на
выбрасываемый экран). Следствие: фаза 4 Epic-09 (фидбек беты)
откладывается до завершения редизайна.

## Что НЕ закрыто (намеренно — входы проектирования эпика)

- **Модель данных «свободно / платежи / резерв» по дням** — в сервисах
  её нет (есть только доходы/расходы/баланс); ядро будущих работ и
  лекарство от P1-боли «цифры карточек противоречат друг другу»
  (единая модель для всех карточек).
- **Инвентаризация механик текущего дашборда, не вошедших в проекцию**
  (из ревью 2026-08-23): вход в «Сверку» с главного экрана (сейчас
  кнопка на вытесняемой KPI-карточке), онбординг-тост нулевого
  баланса, показатель «Доходы за месяц».
- **Пустое состояние щитка у нового пользователя** (из ревью
  2026-08-23): что показывают шапка-вердикт, график и карточки при
  нуле данных — первое впечатление беты.
- **Стоимость загрузки дашборда**: фрагменты всех разделов = данные
  всех страниц при каждом открытии; нужна стратегия (кеш, ленивая
  подгрузка).
- **Мобильная адаптация** (Epic-08): концепция на узких экранах без
  ховера; hover-зависимые механики (тултип легенды, ховер-подписи
  меню); ориентир — полоска меню → нижняя панель.
- **Оформление работ эпиком** и увязка с вопросом №9 ROADMAP (его
  пп. 5 и 7 аудита — жизненный цикл целей — этим обсуждением НЕ
  решены).
- Законсервировано: механика «основного дохода»; настраиваемость
  дашборда (беклог без обязательств).
