## Контекст

Идея владельца (2026-08-22): переосмыслить навигацию — вместо бокового
меню сделать сам дашборд «меню». Метафора электрощитка в подъезде:
лицевая панель с прорезями, через которые видны счётчики (дашборд с
карточками-фрагментами разделов), а «открыв панель», попадаешь внутрь
(полный раздел). Пример: на дашборде кусок календаря — вчера/сегодня/
завтра, клик по нему открывает полный календарь.

При первичном разборе идея разложена на две части: (1) карточки как
живые фрагменты разделов и точки входа с контекстом — сильное ядро,
частично уже реализовано (карточка подушки → цели, «Все операции» →
операции); (2) строгая позиционная привязка «фрагмент ровно там же, где
в полном разделе» — слабое звено (конфликт с приоритетной раскладкой
дашборда, скроллящиеся страницы, мобильная адаптация, техническая цена
shared-element-анимаций в Dash).

Тема перекликается с открытым вопросом №9 из ROADMAP («доработка
инструмента вместо заплаток», пп. 5 и 7 аудита — продуктовые).

## Что РЕШЕНО

1. **Дух важнее буквы** (владелец, 2026-08-22): позиционная привязка
   «ровно то же место экрана» — не жёсткое требование. Ядро идеи —
   карточки как живые фрагменты разделов + переход в раздел с
   сохранением контекста (кликнул «завтра» → календарь открылся на
   завтра).
2. **На дашборде боковое меню убирается совсем** — дашборд сам является
   навигацией.
3. **На остальных экранах меню остаётся, но компактное**: небольшого
   размера, аккуратно вписанное, не нарушающее общую геометрию;
   вариант — только иконки с подписями при ховере (финальная форма —
   на этапе проработки, допустимо «что-то ещё, что больше подойдёт»).
4. **Масштаб — редизайн дашборда**, не пересмотр всей навигации:
   остальные разделы и их устройство остаются на своих местах.
   *Уточнение (2026-08-23, из ревью second-opinion): фактический
   объём = редизайн дашборда + замена каркаса навигации ВСЕХ экранов
   (решения 2, 3, 16 заменяют сайдбар везде, включая свежий
   динамический профиль из Epic-09 фазы 2) — при нарезке эпика и в
   design.md формулировать так, чтобы не занизить оценку.*

5. **Настраиваемость дашборда — отложена** (2026-08-22): сначала
   спроектировать сильный дефолт; настройка «что показывать» — в беклог
   без обязательств (большинство пользователей не меняют дефолты;
   «разные приоритеты» — это один пользователь в разные моменты).
6. **Главный ответ дашборда за 5 секунд** (2026-08-22, предварительно —
   владелец: «по сути это и показывает»): «Свободно сегодня: N ₽» +
   цветовой вердикт (порядок / впереди просадка / проблема) — как
   сжатие «текущего положения дел». Общая картина — второй уровень
   внимания, не первый. Втягивает концепцию вопроса №7 ROADMAP.
7. **Конституционное правило щитка** (владелец, 2026-08-22): каждый
   пункт меню обязан иметь своё представительство-карточку на дашборде,
   иначе идея не работает (на дашборде меню нет — карточки и есть
   навигация). Иерархия ответов определяет размер и позицию карточки,
   но не факт присутствия.
   *Трактовка для будущих разделов (2026-08-23, из ревью
   second-opinion): правило распространяется и на новые предметные
   разделы (импорт, уведомления из бэклога) — новый раздел = новая
   карточка = пересмотр раскладки щитка; это осознанная цена
   конституции. Служебные экраны без предметного содержания
   (настройки, справка) — иконки, не карточки.*

8. **Проекция разделов на щиток — принята** (владелец, 2026-08-22,
   «по таблице все ок»):
   - шапка щитка (не дверь): «Свободно сегодня: N ₽» + вердикт цветом;
   - Календарь → вчера/сегодня/завтра + маркер ближайшей просадки;
     дверь: календарь на кликнутом дне;
   - Цели → топ-цель с прогрессом + сводка остальных («по плану /
     1 отстаёт») + статус подушки одной строкой; дверь: цели с фокусом
     на кликнутой. Подушка живёт внутри карточки целей (принято);
   - Операции → 2-3 недавние + 2-3 предстоящие; дверь: список операций
     с фильтром периода;
   - Аналитика → цифра месяца (топ-категория расходов или
     мини-структура); дверь: аналитика текущего месяца;
   - Wishlist → компактный виджет (не пункт меню, представительство
     сохраняется); дверь: модал/режим покупок;
   - Настройки → служебная иконка в углу, НЕ карточка (принято;
     раздел сейчас 404-заглушка, отложен).
9. **График «деньги с именами» из демо №7 остаётся** (владелец,
   2026-08-22): полосы «свободно / обещано / резерв целей и подушки»
   с вехами целей — центральный элемент дашборда, единый блок с
   шапкой-вердиктом («свободно сегодня» = срез графика на сегодня).
   Демо на моках: https://claude.ai/code/artifact/f9edd8b1-c600-4026-8315-dabc548b2e90

10. **Текущий график заменяется полностью** (владелец, 2026-08-22,
    вариант «а»): бары доходов/расходов + линия баланса уходят с
    дашборда; при желании можно позже вернуть внутри раздела.
11. Узел «что дашборд отвечает за 5 секунд» — закрыт. Следующий этап:
    визуальный эскиз щитка целиком (шапка + график + карточки-двери
    по принятой проекции), делается через /visual.

12. **Семантика полосы платежей зафиксирована** (2026-08-22): деньги,
    которые ещё на счету, но уйдут на уже запланированные платежи
    (регулярные + разовые предстоящие); полоса тает по мере исполнения
    платежей и пересчитывается на границе месяца (формулировка
    согласована с решением 14, пересмотревшим горизонт).
13. **Тултип-пояснение у легенды — принят** (владелец, 2026-08-22):
    при наведении конкретика платежей («аренда 25 авг, коммуналка
    28 авг…») — закрывает часть P1 аудита «продукт не объясняет себя».
14. **Горизонт расчёта — до конца месяца** (владелец, 2026-08-22,
    финальное; пересмотр предыдущего варианта в этой же сессии):
    для первой версии «Зарезервировано» считается по запланированным
    платежам до конца календарного месяца — проще и быстрее.
    **Осознанное ограничение** (владелец знает): платежи начала
    следующего месяца до зарплаты (резерв 1-го при зарплате 5-го)
    не видны в резерве текущего — вспомнить при жалобах беты.
    **Законсервировано**: механика «основного дохода» (пометка
    дохода, после которого обновляются расчёты; аванс+зп) — будущее
    уточнение горизонта, не делать сейчас.

15. **Названия полос графика — финал** (владелец, 2026-08-22):
    Свободно / **Платежи** (оранжевая, запланированные платежи до
    конца месяца) / **Резерв целей и подушки** (синяя). Ранний
    кандидат «Зарезервировано» для оранжевой отброшен из-за коллизии
    двух «резервов» на одной легенде; «Платежи» конкретнее.

16. **Компактное меню на не-дашборд экранах — финал** (владелец,
    2026-08-22): узкая вертикальная полоска иконок слева (~60px),
    подписи при ховере; сверху логотип-«щиток» (возврат на дашборд,
    выделен), внизу аватар; активный раздел подсвечивается (механизм
    есть). **Появление**: при входе в раздел полоска автоматически
    анимированно разворачивается из логотипа вниз («открытие панели»);
    при переходах между разделами не переигрывается (меню в постоянной
    части каркаса); уважает prefers-reduced-motion. Технически дёшево:
    CSS-переход, без серверной логики. Отклонены: верхняя полоска
    (съедает высоту), «всё через дашборд» (два клика на переход),
    скрытое меню по клику/ховеру (находимость, мобильные).
    На мобильных (Epic-08) полоска → нижняя панель иконок.

17. **Анимация переходов «карточка → раздел»** (владелец, 2026-08-22):
    первая версия — БЕЗ эффектов вообще. Идея-кандидат на этап
    полировки (Epic-10): **перелистывание** — дашборд улетает влево,
    раздел въезжает справа (назад — наоборот). При реализации делать
    дешёвую версию (въезд нового экрана, чистый CSS поверх роутинга);
    полную карусель «оба экрана летят» — не делать (хак в Dash).
    Откладывание НЕ удорожает доработку: анимация — слой поверх
    роутинга, обёртка контента уже есть. Shared-element «карточка
    вырастает в страницу» — отклонена окончательно (дорого/хрупко).
18. **Раскладка 8/4 закрыта** (2026-08-22): принятая проекция
    (решение 8) полностью заменяет текущую раскладку; все прежние
    элементы нашли места (wishlist — виджет-строка, подушка — внутри
    карточки целей, таблицы операций — в карточке «Операции»,
    KPI-карточки — вытеснены шапкой-вердиктом и график заменён,
    см. решения 6, 9, 10).

19. **Эскиз v3 принят владельцем** (2026-08-23) как основа реализации
    (находка 1 ревью second-opinion закрыта; артефакт:
    https://claude.ai/code/artifact/019f9b22-b13b-48f6-a362-f9f0b8735f62 ,
    файл `.visual/finfocus-panel-dashboard/v3.html`).
20. **Секвенирование: сначала редизайн, бета потом** (владелец,
    2026-08-23, находка 4 ревью): редизайн доводится до рабочего
    состояния ДО бета-цикла — бета пойдёт уже на новом дашборде;
    сдвиг бета-релиза — осознанная цена (фидбек не тратится на
    выбрасываемый экран). Следствие для ROADMAP: фаза 4 Epic-09

## Что ОТКРЫТО

Продуктовые узлы закрыты (решения 1-18). Остались инженерные — решать
на этапе проектирования реализации, не в этом обсуждении:

- Модель данных «свободно / платежи / резерв» по дням — в сервисах её
  нет (есть только доходы/расходы/баланс); ядро будущих работ и
  лекарство от P1-боли аудита «цифры карточек противоречат друг другу»
  (единая модель для всех карточек). Горизонт «платежей» — до конца
  месяца (решение 14).
- Стоимость загрузки дашборда: живые фрагменты всех разделов = данные
  всех страниц при каждом открытии; нужна стратегия (кеш, ленивая
  подгрузка).
- Мобильная адаптация (Epic-08): как концепция живёт на узких экранах
  без ховера (ориентир уже есть: полоска меню → нижняя панель,
  решение 16). Сюда же hover-зависимые механики концепции:
  тултип легенды графика (решение 13) и ховер-подписи меню
  (из ревью 2026-08-23).
- (из ревью 2026-08-23) Инвентаризация механик текущего дашборда,
  не вошедших в проекцию щитка: вход в «Сверку» с главного экрана
  (сейчас — кнопка на вытесняемой KPI-карточке), онбординг-тост
  нулевого баланса, показатель «Доходы за месяц» из KPI (в проекции
  из аналитики — только расходы). Решить при проектировании эпика.
  Отчёт: `notes/report-2026-08-23.md`.
- (из ревью 2026-08-23) Пустое состояние щитка у нового пользователя:
  что показывают шапка-вердикт («Свободно сегодня» при нуле данных),
  график и карточки-двери без операций и целей — первое впечатление
  беты формирует именно пустой экран (перекликается с P2 аудита
  «пустые состояния графиков деградируют»).
  Отчёт: `notes/report-2026-08-23.md`.
- Оформление работ эпиком и увязка с вопросом №9 ROADMAP (продуктовая
  доработка vs заплатки; вопрос №7 закрывается этим обсуждением).
