## 🟡 Важные проблемы (Should Fix)

### 1. Отсутствует обработка случая "взнос в день резерва после рендера календаря"

**Где:**
- Секция "Ответы на вопросы критика", пункт 4 (строки 451-457)
- Метод `recalculate_current_month_exception()`

**Проблема:**
В ответе на вопрос про тайминг recurring генерации указано: "взнос в 8:00 корректно уменьшит резерв, который будет показан при рендере в 9:00". Однако если пользователь:
1. Открывает календарь в 8:00 (recurring экземпляр "материализован")
2. Делает взнос в 8:30
3. Не перезагружает страницу

Визуально в календаре старый резерв останется до refresh. Это не баг в логике, но может вызвать confusion.

**Почему важно:**
UX проблема — пользователь может не понять что данные обновились.

**Рекомендация:**
Добавить в план реализации примечание о необходимости refresh календаря после создания взноса. Это уже должно работать через `global-transaction-trigger` Store (существующий паттерн в проекте), но стоит явно проверить в integration тестах.

### 2. Метод delete_contribution() в GoalService использует circular import

**Где:**
- Интерфейс `delete_contribution()` (строки 211-227)
- Ссылка на `BudgetReservationService.delete_contribution_transaction()`

**Проблема:**
В алгоритме указано: "Если есть transaction_id — удаляет через BudgetReservationService.delete_contribution_transaction()". Однако GoalService уже импортирует BudgetReservationService для `add_contribution()`. Это создает circular dependency:
- GoalService -> BudgetReservationService (для create_contribution_transaction)
- BudgetReservationService -> GoalService (если добавить зависимость для recalculate)

**Почему важно:**
Circular imports могут вызвать `ImportError` при определенном порядке импортов.

**Рекомендация:**
В GoalService использовать lazy import внутри метода (как уже сделано в существующем коде строка 154 goal_service.py):
```python
def delete_contribution(self, contribution_id: int) -> bool:
    from app.services.budget_reservation_service import BudgetReservationService
    ...
```
Это уже паттерн проекта, просто убедиться что он используется.

## 🟢 Незначительные замечания (Optional)

### 3. Логирование в _cleanup_orphan_exceptions()

**Где:** Метод `_cleanup_orphan_exceptions()` (строки 96-105)

Метод возвращает количество удалённых exceptions, но не логирует какие конкретно даты были удалены. Для debug может быть полезно.

**Рекомендация:**
```python
logger.info(f"Cleaned up {count} orphan exceptions for template {template_id}")
```

### 4. Типизация month параметра

**Где:** `recalculate_current_month_exception(self, user_id: int, month: date | None = None)`

Параметр `month` на самом деле используется как "reference_date" (любая дата в целевом месяце). Название может путать — `month` предполагает первый день месяца.

**Рекомендация:**
Переименовать в `reference_date` для консистентности с `get_budget_progress()` или добавить комментарий что принимается любая дата в месяце.
