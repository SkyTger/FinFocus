## 🟢 Незначительные замечания (Optional)

### 1. Рассмотреть batch update для move_priority_up/down

**Где:** GoalService.move_priority_up(), move_priority_down()

**Замечание:**
Текущая реализация вызывает update_priority() который делает shift-down. При частых кликах на кнопки это может создавать несколько SQL запросов. Для MVP это приемлемо, но в будущем можно оптимизировать.

**Рекомендация (nice-to-have):**
Если пользователи жалуются на производительность - добавить debounce на UI стороне (300ms) или использовать SWAP алгоритм вместо shift-down для кнопок вверх/вниз.

---

### 2. Уточнить поведение при достижении границы приоритета

**Где:** GoalService.move_priority_down()

**Замечание:**
В решении указано "Если уже последний приоритет, возвращает цель без изменений", но визуально пользователь может не понять почему кнопка "вниз" не работает.

**Рекомендация:**
Добавить в UI визуальную индикацию (disabled state) для кнопок когда цель на границе приоритетов. Это уже подразумевается в решении, просто стоит явно отметить в Фазе 3.

---

### 3. Добавить logging для отладки allocation

**Где:** AllocationService.calculate_allocation()

**Замечание:**
В решении AllocationService не использует loguru для отладки. При проблемах с распределением будет сложно диагностировать.

**Рекомендация:**
Добавить logger.debug() для:
- Входных параметров (goals count, budget)
- Результата каждой итерации (goal_id, allocated, remaining)
- Итоговой сводки (total_allocated, total_shortfall)

### Аспект 2: Архитектурное качество

**Статус:** ✅ Хорошо

**Детали:**
- **SRP:** AllocationService отвечает только за расчет распределения, GoalService за CRUD и приоритеты - хорошее разделение
- **OCP:** AllocationService можно расширить новыми стратегиями без изменения GoalService
- **DIP:** Сервисы принимают Session через конструктор (dependency injection)
- **Coupling:** Низкая связность между AllocationService и GoalService (взаимодействие через goals list)

**Комментарий:**
Архитектура соответствует существующим паттернам проекта (сравни с CalendarService, DashboardService). Решение об интеграции budget методов в GoalService логично и не нарушает SRP (это настройки накоплений).
