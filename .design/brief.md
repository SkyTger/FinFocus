# Brief: Три режима накоплений (free/medium/strict)

## Цель
Реализовать режимы накоплений как множители к рассчитанным взносам в цели для гибкого управления интенсивностью накопления. Пользователь выбирает один режим, который применяется ко всем его целям.

## Функциональные требования
- Добавить поле `savings_mode` в модель `User` с тремя значениями: `free`, `medium`, `strict`
- Режим `free` (100%) — минимальные взносы, точно по графику (множитель 1.0)
- Режим `medium` (115%) — +15% буфер для страховки от непредвиденных расходов (множитель 1.15)
- Режим `strict` (150%) — максимизация накоплений для раннего достижения цели (множитель 1.5)
- Применять множитель в `AllocationService.calculate_allocation()` к `monthly_contribution` каждой цели
- Добавить UI селектор режима на странице Goals рядом с кнопкой "Настроить бюджет"
- Сохранять выбранный режим в БД при изменении через UI
- Отображать текущий режим в summary section страницы Goals
- Метод в `GoalService` для получения и обновления `savings_mode`

## Нефункциональные требования
- Обратная совместимость: существующие пользователи получают режим `free` по умолчанию
- Миграция БД должна быть идемпотентной (можно запускать повторно)
- Консистентность: изменение режима немедленно пересчитывает allocation для всех целей
- Производительность: нет дополнительных SQL запросов при расчете allocation (режим передается параметром)

## Ограничения
- Технические: SQLite БД, Python 3.12, Dash UI
- Бизнес: один режим на пользователя (не на отдельную цель)
- Паттерны: следовать существующим паттернам миграций (scripts/migrate_001_*)

## Критерии приёмки
- [ ] Поле `User.savings_mode` добавлено в модель с default='free'
- [ ] `AllocationService.calculate_allocation()` принимает параметр `savings_mode` и применяет множитель
- [ ] UI селектор отображает три режима с описаниями
- [ ] Изменение режима пересчитывает и обновляет UI allocation
- [ ] Миграционный скрипт создан и работает идемпотентно
- [ ] Unit тесты покрывают все три режима в AllocationService
- [ ] Существующие тесты проходят без изменений

## Вне scope (out of scope)
- Индивидуальный режим для каждой цели (MVP: один режим для всех)
- Автоматическое переключение режима на основе финансовой ситуации
- Визуализация прогнозов достижения цели при разных режимах
- Уведомления о необходимости увеличить бюджет в strict режиме
