# Brief: Кассовый календарь с остатками по дням

## Цель
Реализовать ключевую функциональность MVP - кассовый календарь, который визуализирует все запланированные финансовые операции и прогнозирует остаток денежных средств на каждый день месяца. Календарь должен помочь пользователю планировать расходы и избегать кассовых разрывов.

## Функциональные требования

### Визуализация календаря
- Календарь показывает текущий месяц в виде сетки 7x5 (недели x дни)
- Дни недели начинаются с понедельника (first_day_of_week=1)
- Выходные дни визуально отличаются (другой фон)
- Текущий день выделяется особым стилем
- Дни из соседних месяцев показываются затемненными

### Отображение операций
- На каждой дате показываются иконки операций:
  - Доход (↓ зеленая стрелка)
  - Расход (↑ красная стрелка)
  - Несколько операций в день группируются (+N рядом)
- При наведении на дату показывается tooltip со списком операций и суммами

### Расчет остатков
- На каждой дате отображается прогнозируемый остаток средств
- Формула: `остаток(date) = starting_balance + SUM(доходы до date) - SUM(расходы до date)`
- Отрицательный остаток выделяется красным (предупреждение о кассовом разрыве)
- Положительный остаток - зеленым цветом

### Навигация
- Кнопки "<" и ">" для переключения между месяцами
- Кнопка "Сегодня" для быстрого возврата к текущему месяцу
- Заголовок показывает текущий месяц и год (например, "Январь 2026")

### Интерактивность
- Клик по дате открывает модал добавления операции с предзаполненной датой
- Клик по иконке операции открывает модал редактирования этой операции
- После добавления/изменения операции календарь автоматически обновляется

## Нефункциональные требования

### Производительность
- Загрузка календаря < 2 секунды при 100+ операциях
- Переключение между месяцами < 500ms
- Расчет остатков оптимизирован с помощью SQL агрегации
- Кэширование данных между переключениями месяцев

### Адаптивность
- Календарь адаптируется под экраны 1024px+ (desktop)
- На мобильных устройствах (<768px) показывается список дней вместо сетки
- Все элементы интерактивны с touch-устройствами

### Точность расчетов
- Использование Decimal для всех денежных операций
- Точность до копеек (2 знака после запятой)
- Отсутствие погрешностей округления при большом количестве операций

### UX
- Понятная визуализация - пользователь сразу видит проблемные даты (красные остатки)
- Минимум кликов для добавления операции (1 клик по дате → форма с предзаполненной датой)
- Плавные переходы и анимации при переключении месяцев

## Ограничения

### Технические ограничения
- Используется SQLite (development), оптимизация под PostgreSQL (production)
- Dash callbacks - синхронные (без WebSocket real-time обновлений)
- Python backend - расчеты на сервере, не в браузере
- Повторяющиеся операции НЕ входят в scope (Batch 2)

### Бизнес-ограничения
- Только одна активная цель накопления (решение D009)
- Показываем только операции текущего пользователя (user_id=1 hardcoded в MVP)
- Взносы в цели НЕ учитываются в кассовом календаре (цели накапливаются отдельно)
- Период отображения: текущий месяц ± 12 месяцев (валидация в API)

### Scope ограничения
- Категории операций не используются в календаре (показываются все операции)
- Фильтрация по типам операций - вне scope
- Экспорт календаря - вне scope
- Push-уведомления о кассовых разрывах - вне scope

## Критерии приёмки

### Визуализация
- [ ] Календарь отображает сетку 7x5 дней с правильными датами месяца
- [ ] Выходные дни визуально отличаются от будних
- [ ] Текущий день выделяется другим цветом
- [ ] Дни соседних месяцев показываются затемненными

### Операции
- [ ] Иконки доходов и расходов отображаются на правильных датах
- [ ] При нескольких операциях в день показывается "+N"
- [ ] Tooltip показывает список всех операций дня с суммами
- [ ] Клик по дате открывает модал создания операции с предзаполненной датой

### Остатки
- [ ] Остаток рассчитывается правильно по формуле: starting_balance + доходы - расходы
- [ ] Отрицательные остатки показываются красным цветом
- [ ] Положительные остатки - зеленым
- [ ] Остаток 0 или близкий к нулю - желтым (предупреждение)

### Навигация
- [ ] Кнопка "<" переключает на предыдущий месяц
- [ ] Кнопка ">" переключает на следующий месяц
- [ ] Кнопка "Сегодня" возвращает к текущему месяцу
- [ ] Заголовок показывает корректный месяц и год

### Производительность
- [ ] Загрузка календаря на 100 операциях < 2 сек
- [ ] Переключение месяцев < 500ms
- [ ] Отсутствие задержек при открытии модалов

### Корректность данных
- [ ] Операции отображаются на правильных датах
- [ ] Расчеты остатков точны до копейки
- [ ] После создания/изменения операции календарь автообновляется
- [ ] Удаление операции обновляет календарь и пересчитывает остатки

## Вне scope (out of scope)

### Не входит в Фазу 3
- Повторяющиеся операции (is_recurring=True) - реализуется в Batch 2
- Множественные цели накопления - реализуется в Batch 2
- Фильтрация операций по категориям/типам - Batch 3
- Экспорт календаря (PDF, Excel) - Batch 3
- Уведомления о приближении кассовых разрывов - Batch 4
- Импорт операций из банковских выписок - Batch 4
- Mobile-first версия календаря - Batch 3
- Drag-and-drop для перемещения операций между датами
- Inline редактирование операций прямо в календаре
- Цветовые метки для категорий операций
- Graphical прогноз кассового потока (линейный график)
