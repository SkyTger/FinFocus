# Brief: Финансовая подушка безопасности (протокол 4.1)

## Цель
Реализовать backend-логику и UI карточки/модала финансовой подушки на странице `/goals`. После завершения пользователь сможет настроить целевой размер подушки, минимальный порог и использовать калькулятор сценариев для определения оптимальной суммы.

## Функциональные требования

### Backend
- FR-01: Добавить 3 новых поля в модель User: `cushion_target` (Decimal), `cushion_threshold` (Decimal), `cushion_threshold_manual` (Boolean)
- FR-02: Создать TypedDicts `CushionSettings` и `CushionScenario` в новом модуле `app/schema/cushion.py`
- FR-03: Реализовать `SafetyCushionService` с методами:
  - `get_settings(user_id)` - получение настроек с вычисленными полями (current_amount, progress)
  - `update_settings(user_id, target, threshold, threshold_manual)` - обновление настроек
  - `reset_settings(user_id)` - сброс настроек (обнуление)
  - `calculate_recommendation(scenarios, mode)` - расчет рекомендации по сценариям

### UI Карточка
- FR-04: Карточка подушки отображается вверху страницы /goals, над блоком бюджета
- FR-05: Состояние "Не настроена" (target=0): текст приглашения + кнопка "Настроить"
- FR-06: Состояние "Настроена" (target>0): цель, текущая сумма, прогресс-бар с маркером порога
- FR-07: Клик на кнопку "Настроить" открывает модал настройки

### UI Модал
- FR-08: Поле "Цель подушки" - число >= 0
- FR-09: Поле "Минимальный остаток" (порог) - по умолчанию 30% от цели
- FR-10: Автопересчет порога при изменении цели (если threshold_manual=False)
- FR-11: При ручном изменении порога установить threshold_manual=True
- FR-12: Collapsible секция "Рассчитать по сценариям" с возможностью добавить до 5 сценариев
- FR-13: Режим расчета: "Сумма всех сценариев" или "По самому дорогому"
- FR-14: Кнопка "Применить" копирует рекомендацию в поле цели
- FR-15: Кнопка "Сбросить" обнуляет все настройки
- FR-16: Кнопка "Сохранить" записывает в БД и закрывает модал

## Нефункциональные требования
- NFR-01: Время расчета текущего баланса < 100ms (используется CalendarService.get_balance_on_date)
- NFR-02: Сценарии НЕ сохраняются в БД (только в UI state через dcc.Store)
- NFR-03: Все callbacks следуют ADR-003 (guard clauses для Pattern-Matching)
- NFR-04: Unit тесты покрывают все методы SafetyCushionService

## Ограничения
- Технические: user_id = 1 (hardcoded в UI, MVP single-user)
- Технические: Миграция через пересоздание БД (dev stage, см. TODO в database.py)
- Бизнес: Подушка не является целью накопления (Goal), это отдельная сущность в User
- Бизнес: current_amount = текущий баланс через CalendarService, не отдельное поле

- [ ] Карточка подушки отображается вверху /goals (два состояния)
