# Brief: Категоризация транзакций и механизм сверки остатков

## Цель
Добавить категоризацию финансовых операций с "ленивым" подходом (категория опциональна) и механизм сверки расчетного баланса с фактическим для корректировки расхождений.

## Функциональные требования
- FR1: Создание модели Category как справочника с предзаполненными категориями расходов и доходов
- FR2: Добавление nullable category_id к Transaction (связь Many-to-One)
- FR3: Добавление нового TransactionType.ADJUSTMENT для корректирующих операций
- FR4: CategoryService для получения и seed категорий
- FR5: ReconciliationService для создания корректировок баланса
- FR6: Выбор категории в формах создания/редактирования транзакций (опционально)
- FR7: Наследование category_id из шаблона в recurring экземпляры
- FR8: Модал "Сверка" на странице календаря с показом расчетного баланса
- FR9: Фильтр "Без категории" в списке транзакций
- FR10: Отображение категории с иконкой в таблице транзакций

## Нефункциональные требования
- NFR1: Seed категорий должен быть idempotent (можно запускать повторно)
- NFR2: Производительность: выбор категории не должен блокировать создание транзакции
- NFR3: ADJUSTMENT транзакции корректно обрабатываются в CalendarService (могут быть положительными или отрицательными)
- NFR4: Миграция существующих данных — все category_id = NULL (нормальное состояние)

## Ограничения
- Category модель без пользовательских кастомных категорий (на данном этапе)
- Нет Account модели (несколько кошельков) — только один баланс
- Нет bulk-операций с категориями (chips, bulk edit) — перенесено в Батч 3.2
- Интеграция только с Calendar и Transactions страницами

## Критерии приемки
- [ ] Пользователь может создать операцию с категорией или без
- [ ] Категория отображается в списке транзакций (иконка + название)
- [ ] Фильтр "Без категории" работает в списке транзакций
- [ ] Recurring операции наследуют category_id из шаблона
- [ ] Кнопка "Сверка" на календаре открывает модал
- [ ] Модал показывает расчетный баланс и принимает фактический
- [ ] При создании корректировки баланс в календаре обновляется
- [ ] ADJUSTMENT корректно влияет на баланс (может быть + или -)
- [ ] seed_default_categories() idempotent
- [ ] Минимум 15 unit тестов для новой функциональности

## Вне scope (out of scope)
- Пользовательские кастомные категории (создание/удаление)
- Account модель и множественные кошельки
- Быстрые кнопки категорий (chips) в списке транзакций
- Режим "разобрать хвост" (bulk assign category)
- Графики и диаграммы по категориям (Батч 3.2)
