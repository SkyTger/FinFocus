# Brief: Интеграция бюджета целей с кассовым календарём

## Цель
Связать систему управления накопительными целями с кассовым календарём через два режима резервирования бюджета, позволяя пользователям визуально планировать накопления и отслеживать влияние на реальный баланс.

## Функциональные требования

### FR-1: Два режима резервирования бюджета
- **Режим "Фиксированная дата"**: recurring операция "Резерв на цели" на X-е число каждого месяца (сумма = `monthly_savings_budget`)
- **Режим "Из остатка"**: при каждом взносе создается операция "Взнос: {цель}" на текущую дату

### FR-2: Динамический бюджет
- Формула: `доступный_бюджет = monthly_savings_budget - сумма_взносов_в_текущем_месяце`
- Обновление при каждом взносе
- Отображение на странице Goals

### FR-3: Визуализация прогресса бюджета
- Карточка "Бюджет накоплений (месяц год)" на странице Goals
- Прогресс-бар с цветовой индикацией (0-70% зеленый, 70-90% желтый, 90-100% оранжевый, >100% красный)
- Режимозависимый текст: "Распределено X из Y" или "Внесено X из Y"

### FR-4: Операция "Резерв на цели"
- Новый тип транзакции: `TransactionType.SAVINGS_RESERVE`
- Системная операция (read-only в UI календаря)
- Влияет на баланс как EXPENSE (уменьшает доступные средства)
- Генерируется RecurringService при режиме "Фиксированная дата"

### FR-5: Операции "Взнос: {цель}"
- Новый тип транзакции: `TransactionType.SAVINGS_CONTRIBUTION`
- Создается при взносе в режиме "Из остатка"
- Редактируемая (можно изменить сумму)
- Связь с GoalContribution через description или FK

### FR-6: Переключение режимов
- В модале настройки бюджета добавить RadioButtons для выбора режима
- Dropdown для выбора дня месяца (1-31) в режиме "Фиксированная дата"
- При переключении:
  - "Из остатка" -> "Фиксированная дата": создать recurring шаблон, сохранить историю взносов
  - "Фиксированная дата" -> "Из остатка": остановить recurring шаблон (soft delete), новые взносы создают операции

### FR-7: Anchored-алгоритм для коротких месяцев
- Переиспользовать RecurringService._get_anchored_date() для обработки 31-е -> 28/29/30

## Нефункциональные требования

### NFR-1: Производительность
- Расчет доступного бюджета < 50ms
- Время загрузки календаря с "Резерв на цели" < 1.5 сек

### NFR-2: Совместимость
- Обратная совместимость с существующими GoalContribution (без операций в календаре)
- Миграция существующих данных не требуется (режим "Из остатка" по умолчанию без создания операций для старых взносов)

### NFR-3: Type Safety
- TypedDicts для всех новых структур данных в app/schema/
- Percent NewType для threshold_percent (существующий паттерн)

## Ограничения

### Технические ограничения
- SQLite (нет Alembic миграций в MVP, но ALTER TABLE поддерживается)
- Один пользователь (user_id=1, как везде в MVP)
- Существующий flush/commit contract в сервисах

### Бизнес-ограничения
- Перенос недовнесенного бюджета на следующий месяц - вне scope MVP
- Автораспределение остатка в конце месяца - вне scope MVP
- Интеграция с подушкой безопасности - вне scope MVP

## Критерии приёмки
- [ ] Пользователь может выбрать режим резервирования в модале бюджета
- [ ] В режиме "Фиксированная дата" операция "Резерв на цели" появляется в календаре на выбранную дату
- [ ] В режиме "Из остатка" при взносе создается операция "Взнос: {цель}"
- [ ] Карточка бюджета показывает корректный прогресс с учетом всех взносов месяца
- [ ] Переключение режима сохраняет историю взносов
- [ ] Операция "Резерв на цели" не редактируется вручную (системная)
- [ ] Unit тесты покрывают все новые сервисы (>90% coverage)
- [ ] Black + Flake8 без ошибок

## Вне scope (out of scope)
- Перенос недовнесенного бюджета на следующий месяц
- Автоматическое распределение остатка бюджета в конце месяца
- Предупреждения о недостатке средств для выполнения плана
- История изменений режима (аудит)
- Интеграция с подушкой безопасности
- Уведомления "Пора вносить взнос"
