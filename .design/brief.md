# Brief: Исправление багов режима резервирования fixed_date

## Цель
Обеспечить корректную работу режима `fixed_date` при переключении режимов резервирования и изменении взносов/бюджета путём переиспользования существующих recurring шаблонов и автоматического пересчёта exceptions.

## Функциональные требования
- При переключении режимов (fixed_date -> from_balance -> fixed_date) с тем же днём месяца шаблон должен реактивироваться, а не создаваться заново
- Exceptions для текущего месяца должны сохраняться при переключении режимов (если день тот же)
- При изменении дня месяца старые orphan exceptions должны удаляться
- При удалении взноса exception должен пересчитываться
- При изменении суммы взноса exception должен пересчитываться
- При изменении monthly_savings_budget exception должен пересчитываться
- get_budget_progress() должен показывать взносы единообразно для обоих режимов

## Нефункциональные требования
- Обратная совместимость с существующими данными
- Не требуется миграция схемы БД
- Логирование всех операций пересчёта exceptions
- Производительность: пересчёт только для будущих дат резерва

## Ограничения
- Не изменять схему базы данных (Transaction, User)
- Сохранить существующий API сервисов
- Использовать существующий RecurringService.create_exception() для создания/обновления exceptions
- День месяца ограничен 1-28 в UI (валидация уже существует)

## Критерии приёмки
- [ ] Переключение fixed_date -> from_balance -> fixed_date сохраняет exceptions (тот же день)
- [ ] Досрочный взнос корректно уменьшает резерв в календаре после переключения режимов
- [ ] Удаление взноса корректно увеличивает резерв (пересчёт exception)
- [ ] Изменение бюджета корректно обновляет резерв (пересчёт exception)
- [ ] UI показывает "Внесено: X / Y" единообразно для обоих режимов
- [ ] 100% тестов проходят (существующие + новые)
- [ ] Нет регрессий в существующей функциональности

## Вне scope (out of scope)
- Миграция данных существующих пользователей (пересчёт произойдёт при следующем взносе)
- Изменение UI логики переключения режимов
- Поддержка нескольких шаблонов резерва на пользователя
- Обработка exceptions для прошедших дат резерва
