# 0005 — Повторяющиеся операции (Recurring Transactions)

## ADR-style Summary:

- **Context**: FinFocus — приложение для планирования бюджета. Core MVP (Батч 1) завершен. Следующий этап — Батч 2: Enhanced Planning, ключевая фича которого — повторяющиеся операции (зарплата, аренда, подписки).

- **Problem Statement**: Пользователи вводят одни и те же операции каждый месяц (зарплата, аренда, коммуналка). Это неудобно и создает риск забыть ввести операцию. Нужна автоматическая генерация повторяющихся операций с возможностью редактирования отдельных экземпляров.

- **Decision**: Гибридная архитектура с Anchored-алгоритмом:
  - **Шаблоны (templates)** хранятся в таблице Transaction с `is_recurring=True`
  - **Исключения (exceptions)** — как обычные транзакции со ссылкой на родительский шаблон через `recurring_parent_id`
  - При запросе календаря RecurringService генерирует **виртуальные экземпляры** из шаблонов
  - **Anchored-алгоритм**: сохраняем исходный день месяца (31 января → 28 февраля → 31 марта)

- **Alternatives**:
  1. **Eager materialization** (создавать все экземпляры сразу) — отвергнуто из-за сложности удаления/изменения серии
  2. **Sliding algorithm** (28 февраля → 28 марта) — отвергнуто, пользователи ожидают возврат к исходному дню
  3. **Отдельная таблица RecurringTemplate** — отвергнуто, избыточная сложность

- **Consequences**:
  - (+) Минимальное хранилище (только шаблоны + исключения)
  - (+) Легко изменить/удалить всю серию (один шаблон)
  - (+) Понятная логика для пользователей (Anchored)
  - (-) Сложность генерации виртуальных экземпляров
  - (-) Необходимость фильтрации шаблонов во всех запросах CalendarService

## Generic Principles (MUST follow):

1. **Баланс и простота**: Избегай оверинжиниринга. Решения должны быть самыми простыми из возможных, но функциональными и надежными.

2. **Никакого легаси**: Удаляй устаревший код. Обратная совместимость не требуется.

3. **Стандарты кодирования (CLAUDE.md)**:
   - Python 3.12 с type annotations
   - Docstrings на русском языке
   - Guard clauses в начале функций
   - Session management: сервисы используют `flush()`, caller делает `commit()`

4. **Pattern-Matching Callbacks (ADR-003)**: При использовании `ALL` в callbacks обязательна проверка `ctx.triggered[0].get('value') is None`.

5. **Тестирование**: Каждый новый метод сервиса должен иметь unit тесты. Покрытие edge cases обязательно.

6. **Детализация**: Все изменения должны быть атомарными и понятными. Один коммит — одна логическая единица работы.
