# 0001 — Рефакторинг FinFocus: устранение техдолга

## ADR-style Summary:

- **Context**: Code review выявил критические проблемы в кодовой базе FinFocus: утечки соединений БД (новый engine/session в каждом callback), ~200 строк дублирующегося кода в transactions.py, отсутствие логирования, два разных класса ValidationError, silent error handling.

- **Problem Statement**: Текущая архитектура создаёт риски при масштабировании: утечки памяти при нагрузке, сложность поддержки из-за copy-paste кода, невозможность отладки без логов, плохой UX из-за скрытых ошибок валидации.

- **Decision**: Провести поэтапный рефакторинг с приоритетом: (1) централизация session management, (2) добавление loguru, (3) унификация ValidationError, (4) устранение дублирования, (5) улучшение обработки ошибок.

- **Alternatives**:
  - Полная переписка — отвергнута (слишком долго, MVP работает)
  - Минимальные фиксы — отвергнута (не решает системные проблемы)
  - Поэтапный рефакторинг — выбрано (баланс скорости и качества)

- **Consequences**:
  - (+) Устранение утечек соединений
  - (+) Сокращение кода на ~200 строк
  - (+) Возможность отладки через логи
  - (+) Понятные ошибки для пользователя
  - (-) ~7 часов работы
  - (-) Риск регрессий в callbacks

## Generic Principles (MUST follow):

1. **Баланс и простота**: Избегай оверинжиниринга. Решения — самые простые из возможных, но функциональные и надежные.

2. **Никакого легаси**: Удаляй устаревший код. Обратная совместимость не требуется.

3. **Стандарты кодирования**:
   - Python 3.12, type annotations обязательны
   - Docstrings на русском языке
   - black для форматирования, flake8 для линтинга

4. **Логирование через loguru**: Все операции CRUD, ошибки, важные события.

5. **Session management**: Всегда через context manager `get_db_session()`.

6. **Тестирование**: После каждого шага — запуск приложения, проверка CRUD операций.
